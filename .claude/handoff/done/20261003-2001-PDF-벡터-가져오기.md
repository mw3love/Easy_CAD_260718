## 할 일 — 항목33 PDF 벡터 가져오기

- 무엇: AutoCAD 등이 낸 **벡터 PDF**의 선·곡선·채움·글자를 좌표·색 그대로 `.ecad` 도형으로 옮긴다
  (PyMuPDF `get_drawings()`/텍스트, AI 불필요).
- 이미 있는 것: 실험 도구 `tools/pdf_vector_probe.py`, 실험 기록 `docs/history/2026-10.md`
  "사진→도면 0단계 재시험 — CAD 출력 PDF로"(9,487개 아이템 ~3초, 정확·무료). 그 결과로 만든 도면이
  리포 루트의 `UHD-06_벡터변환_시험.ecad`(gitignore 대상, 이 PC에만 있음).
- 이미 알려진 함정 2개(`docs/pitfalls.md`): ⓐ 수평·수직 직선은 `rect`가 0두께라 `Rect.intersects()`가
  거짓 → 구획 필터에서 사라짐(살짝 넓혀 검사) ⓑ AutoCAD PDF는 굵은 선을 삼각형 채움 여러 개로 냄 →
  끊긴 지점마다 별도 다각형으로 나눌 것.
- 계획서가 적어 둔 착수 전 확인: 9천 개 규모 문서의 편집 체감, DXF 가져오기와의 역할 구분
  (원본 DWG가 있으면 그쪽이 우선).
- ⚠ PyMuPDF(`fitz`)는 이 PC엔 있지만 `requirements.txt`에 없다 — 앱 기능이 되면 의존성 추가 여부를
  인터뷰에서 정해야 한다(배포판 크기·라이선스 AGPL 확인 필요).

## 진행 방식 (이 프로젝트·사용자 관례 — 오늘 세션에서 확인된 것)

1. **착수 시 deep-interview**: 결과가 크게 달라지는 것만 `AskUserQuestion`으로 묻고(추천안 맨 앞
   "(추천)"), 사소한 건 정하고 한 줄 알린다. 후보 질문: 진입점(열기 Ctrl+O에서 .pdf 확장자 분기 vs 삽입 메뉴),
   여러 쪽 PDF 처리(한 쪽 선택 vs 쪽마다 탭/용지틀), 글자를 글자 도형으로 vs 패스로, 굵은 선 처리,
   PyMuPDF 의존성.
2. 끝의 기준을 먼저 정하고(규칙 9), 실제 PDF로 렌더 비교 + 실제 창 확인(규칙 11-d) 후 보고.
3. 회귀 테스트는 `tests/test_part22_*.py`로(현재 1163개 전부 통과, part21까지 있음). PDF 여는 테스트는
   `pytest.importorskip("fitz")`(part19 선례).
4. 함정: 오프스크린 테스트에서 앱이 QMessageBox를 띄우면 스위트가 무한 대기 — 전체 실행은
   `timeout 400 python -m pytest tests -q -p no:cacheprovider`로. QSettings를 쓰는 새 기능은
   `EASYCAD_SETTINGS_ORG`로 테스트 격리(항목32 선례).
5. 완료하면 `docs/history/2026-10.md` 끝에 경위, 계획서 §8 항목 취소선, `CLAUDE.md` "현재 상태" 롤링
   갱신(가장 오래된 최근 항목 1~2개 삭제), 커밋은 물어보고(트레일러 포함).
