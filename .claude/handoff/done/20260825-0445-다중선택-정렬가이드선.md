# 다중선택 이동 시 정렬 가이드선 지원 — deep-interview로 기준 확정 후 구현

생성: 2026-08-25 04:45

## 완료 요약

deep-interview로 (a) 그룹 bbox 전체 기준 확정(대표도형·개별스냅 기각) + 격자 스냅도
같은 방식으로 함께 지원하기로 확정. `core_view.py`의 `_apply_smart_snap`/신규
`_multi_align_snap`/`_apply_grid_snap_move`/`_align_candidates`(exclude_items 확장)를
수정 — 2개 이상 선택 시 각 도형의 tight bbox 합집합을 단일 가상 도형으로 취급해 정렬·
격자 스냅 모두 적용하고, 스냅되면 선택된 도형 전부가 같은 델타로 함께 이동(상대 배치
유지). 옛 "다중선택 스킵" 회귀 가드였던 `test_smart_align_skips_multiselect`를
`test_smart_align_multiselect_uses_group_bbox`로 교체 + 신규 pytest 2종 추가
(`tests/test_part3_transform_snap.py`), 전체 스위트 953종 통과. 실조건검증: offscreen
아닌 실제 창에서 API 직접호출로 그룹 정렬 스냅(가이드선 렌더 스크린샷 확인)·격자 스냅
둘 다 확인 완료.

## 배경

사용자가 실사용 중 두 가지를 지적했다: ① 도형 2개 이상 선택해서 함께 이동하면 정렬
가이드선이 안 뜬다. ② 직각(엘보) 화살표를 이동할 때도 정렬 가이드선이 안 뜬다(도형은
화살표에 정렬되는데 반대).

②는 같은 세션(2026-08-25)에서 이미 원인 파악 후 구현·커밋 완료됐다(커밋 `74b50dd`,
`_PolyArrowItem._nudge_segment_axis` + `_AnnotatorView._apply_segment_align_snap`,
`core_view.py`/`core_shapes.py`). 이 인계 파일은 ①(다중선택)만 남은 것이다.

## 원인

`easycad/canvas/core_view.py`의 `_apply_smart_snap()`(1219줄 부근)이 시작부터

```python
sel = [it for it in self.scene().selectedItems() if it.parentItem() is None]
if len(sel) != 1:
    return
```

로 게이트돼 있어 다중선택이면 즉시 return한다. 같은 게이트가 `_apply_grid_snap_move()`
(1270줄 부근)에도 있어 격자 스냅도 다중선택에서 똑같이 안 먹는다 — 두 기능이
"단일 선택 전용"으로 처음부터(2026-07 "2e" 기능 도입 시점부터) 일관되게 설계돼 있었다.
즉 버그가 아니라 애초에 다중선택까지 스코프가 넓혀진 적이 없는 상태다.

## 왜 바로 구현하지 않았나

"여러 도형이 선택된 상태에서 무엇을 기준으로 정렬할지"가 정해져 있지 않다. 후보:

- **(a) 그룹 전체 bbox를 하나의 가상 도형처럼 취급** — 선택 그룹의 bounding box를
  `_apply_smart_snap`의 `nr`처럼 다뤄 다른 도형과 정렬. 구현은 상대적으로 단순(기존
  `_align_candidates`/`_align_match`를 그대로 재사용 가능)하지만, 그룹 안 개별 도형이
  아니라 그룹 전체 윤곽 기준이라 "안의 어떤 도형이 실제로 맞았는지"가 안 보일 수 있다.
- **(b) 대표 도형(마지막 클릭/드래그 시작 도형) 하나만 기존 단일-도형 로직 그대로 적용** —
  구현이 가장 쉽지만(사실상 게이트만 완화) 나머지 도형은 대표 도형에 딸려가므로 "내가
  안 고른 도형 기준으로 정렬된다"는 체감이 어색할 수 있다.
- **(c) 그룹 내 각 도형이 독립적으로 정렬 후보를 찾아 각자 스냅** — 가장 정교하지만
  여러 스냅이 동시에 발동해 과발화·가이드선 난립 위험이 크다(2026-08-01에 실제로
  "과발화"가 문제였던 전례 있음, `docs/history/2026-08.md` 참조).

착수 전에 `deep-interview` 스킬로 사용자와 이 기준부터 확정할 것 — 코드를 먼저 짜지
말고 질문으로 시작한다(전역 CLAUDE.md 규칙 6).

## 관련 코드 위치

- `easycad/canvas/core_view.py`
  - `_apply_smart_snap()` — 약 1219줄, `len(sel) != 1` 게이트.
  - `_apply_grid_snap_move()` — 약 1270줄, 동일 게이트(격자 스냅도 같이 다중선택 지원
    여부를 결정해야 할 수 있음 — deep-interview에서 함께 물을 것).
  - `_align_candidates()`/`_align_match()`/`_build_align_guides()` — 후보 스캔·매칭·
    가이드선 생성 로직, 그대로 재사용 가능.
  - `_apply_segment_align_snap()`(2026-08-25 신규) — 같은 로직을 세그먼트 드래그에
    이식한 참고 사례(다만 이건 "축 하나만" 케이스라 다중선택과 성격이 다름).
- 참고 테스트: `tests/test_part3_transform_snap.py`의 `test_smart_align_*` 계열
  (`test_smart_align_skips_multiselect`가 현재의 "다중선택은 스킵" 동작을 고정하는
  테스트 — 구현 시 이 테스트의 기대값을 바꿔야 함).
