## 할 일
1. `deep-interview` 스킬을 중간점검 모드로. 먼저 사용자에게 「써 보며 적은 메모」를 받는다(없으면 그것부터 묻기 — 실제 사용이 재료).
2. 점검 축(Claude가 10-19에 본 증거 — 인터뷰 재료로 내놓되 결정은 사용자):
   - **안 깨지게 지키기**: 웹 자동 시험(`npm test` 89)은 순수 계산만. 화면 동작은 Playwright로 그때그때 손 시험 — 10-19에도 시험 중에야 버그 하나(대기 중 Enter가 기존 글 지움) 발견.
     제안: 매일 쓰는 흐름(칠판 열기 → 메모 → KAIROS 묻고 붙이기 → 프레임 → 발표 → 저장·새로고침)을 화면 자동 시험으로 묶기.
   - **화면 배치**: 960px 좁은 창에서 뜬 대화창이 칠판의 약 40%, 네 구석 카드가 그 위에 겹침(카드 접기로 완화). 좁은 창 「아이콘만 막대」는 10-07 결정(「아이콘만은 알아보기 어려움」)과 부딪힘 — 어느 쪽이 이기나.
   - **글쇠 규칙**: 고른 것에 따라 같은 글쇠 뜻이 바뀜(숫자 도구 1~7·Shift+H/V vs 바로 치기) — 규칙표 한 장으로 정리할지.
   - **데스크톱과의 틈**: 웹 새 칸(프레임·메모 등)은 데스크톱 `_WEB_ONLY_KEYS`에 보존만 — 언제 메울지.
   - **목표 확인**: 완료 기준 「일주일 내내 매일 켜서 쓴다」를 지금 바탕이 넘는지, 안 쓰는 기능은 무엇인지.
3. 인터뷰 결과로 계획서 §8 항목61의 다음 순서를 고쳐 쓰고(다잡기 먼저 / 새 기능 먼저), 사용자 확인 뒤 착수.
