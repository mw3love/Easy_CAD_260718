# 마인드맵: 빈 노드를 취소하면 남는 고아 화살표 정리 (계획서 §8 항목26)

## 배경

남은 후보 중 2순위(사용자 결정 2026-10-03: 작은 개선 → 이것 → 코드 정리 → LOD). 실제로 눈에 보이는 버그이고 범위가 작다.

## 현상과 원인(이미 규명됨)

- Tab/Enter로 마인드맵 자식·형제 노드를 만들면 `host_mindmap.py`의 `mm_create_child`/`mm_create_sibling`/
  `mm_create_in_direction`이 새 노드+화살표를 **즉시 커밋**(`push_undo_add_many`)한 뒤 편집모드로 들어간다.
  빈 텍스트인 채로 편집을 취소(Esc 등)해도 되돌리는 코드가 없어 빈 노드·화살표가 남는다.
- 2026-08-24 도입 때 의도적으로 최소범위로 남겨 둔 것. 상세: `docs/EasyCAD_계획.md` §8 항목26,
  `docs/history/2026-08b.md` "최종 검수 Phase 6" 부근(3185줄 근처).
- 고치려면 "이 편집이 방금 만든 빈 노드의 첫 편집인지" 추적 상태가 새로 필요(작은 기능 추가).

## 할 일

1. 착수 시 짧은 deep-interview(AskUserQuestion, 추천안 맨 앞): 빈 텍스트 판정 기준(공백만도 빈 것?), 노드+화살표 둘 다
   지울지, 되돌리기 기록에 흔적을 남길지(추천: 만든 기록째 없애 Ctrl+Z에 안 보이게), Esc뿐 아니라 다른 곳 클릭으로
   편집이 끝나도 같게 할지.
2. 끝 기준(제안): 실제 창에서 Tab → 아무것도 안 치고 Esc → 노드·화살표가 남지 않음, 글자를 쳤다 지운 경우 규칙대로,
   Ctrl+Z/다시실행이 꼬이지 않음, 저장 파일에 고아 없음, 전체 테스트 통과.
3. 함정 메모: QTest.keyClicks로 한글 자모를 치면 프로세스가 exit 127로 죽는다(테스트 도구 한계, `docs/pitfalls.md`) —
   한글은 setText로.
