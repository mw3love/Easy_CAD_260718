계획: `docs/EasyCAD_계획.md` §8 「웹 칠판 트랙」 항목61. 같은 날 ⓐ 바탕 부품 비교(→ tldraw 5.5.2 확정)와 ⓑ 칠판 바탕(`web/` — .ecad 열기·서버 저장·.ecad 저장 왕복)을 끝냈다.
다음은 ⓒ **대화**. 결정(사용자): 대화는 둘 다 — ① 앱 안 KAIROS 대화창(칠판을 보며 고치기·내 자료 질문) ② 크롬 확장으로 GPT·Claude·Gemini 웹 답을 칠판에 보내기. 한 번에 둘 다 만들지 않는다.

## 할 일
1. 둘 중 무엇을 먼저 할지 사용자에게 묻는다(`AskUserQuestion`, 열린 질문 — 계획서 항목61 「열린 질문」). 판단 재료:
   - ① 앱 안 KAIROS: 이미 데스크톱에 게이트웨이(`easycad/ai/gateway.py`, 키는 `easycad-gateway.key` 전용 — memory 참조)와 보드 설계서(`pdf_to_board.py`)·배치(`host_blocks.py`)가 있다.
     웹에선 서버(`web/server.py`)가 Python 엔진을 바로 부를 수 있다(같은 repo — 그래서 repo 안에 둠). 크레딧을 쓴다.
   - ② 크롬 확장: 사용자는 하루 70% 브라우저, 크롬 확장을 여럿 만들어 봄, 크레딧 0, 이미 매일 쓰는 AI 웹에 올라탐. 칠판(`?board=이름`)에 PUT하거나 창고로 보냄.
   - 둘 다 "답을 칠판에 붙이는" 같은 받는 쪽(창고 ⓓ와 맞물림)이 필요하다 — 어느 쪽이든 먼저 그 모양을 정한다.
2. 고른 쪽의 끝 기준을 먼저 정하고(규칙 9) 만든다. 화면 원칙: 기본 2분할(작업공간 + AI 대화창) + 창고 — 웹 칠판엔 항목51 「가운데 칸 하나」·「양옆 고정 칸 없음」을 적용 안 함(데스크톱엔 그대로).

## 알아둘 것
- 실행: `cd web && npm run dev`(5190, 저장은 `python web/server.py` 5191로 넘김) · 시험 `npm test` · 데스크톱 회귀 `tests/test_part49_web_export.py`.
- tldraw 함정(`docs/pitfalls.md` 끝): meta에 undefined 금지, 마우스 모양 이름 `cross`, 화살표 쪽 `canBind`, 보드 안 도형 x·y는 보드 기준.
- 사용자가 직접 할 일(진행 여부 물어볼 것): tldraw 취미 라이선스 신청, 감시 PC 서버 사용 보안 확인 → 되면 감시 PC에서 `web/README.md`대로 켜기.
- 남은 ⓑ 자잘한 것: 표·곡선 화살표 휨·회전 미지원, 펜·그림을 웹에서 새로 넣어 내보내기 미확인.
