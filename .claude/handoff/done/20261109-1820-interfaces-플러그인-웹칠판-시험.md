# interfaces 플러그인(better-interface)을 Magic Board 웹 칠판에 시험

생성: 2026-11-09 18:20

## 배경

2026-11-09 `~/.claude` 세션에서 디자인 엔지니어 Jakub Krehel이 공개한 Claude 스킬 묶음 `jakubkrehel/skills`(MIT, v1.19.1, 스킬 15개)를 검토하고, `interfaces@interfaces` 플러그인을 user 범위로 설치했다(`~/.claude` 커밋 `3812717`). 원래 인계 파일은 `~/.claude/handoff/done/20261109-1810-interfaces-플러그인-웹화면-시험.md`. 시험 대상으로 이 리포의 `web/`(Magic Board 웹 칠판, React 18 + Vite)을 골랐다 — AROS `tools/dashboard.html`은 한 파일 2만 줄이라 범위가 너무 커서 뺐다.

검토에서 확인한 것:

- 핵심 스킬 `better-interface`는 화면 하나를 접근성·배치·문구·글자·색·UI 마감의 6개 분야로 검사하고, HIGH/MEDIUM/LOW로 순위를 매긴 보고서 한 장을 준다. 지적마다 `파일:줄` 근거를 요구한다. 원본: `~/.claude/plugins/cache/interfaces/interfaces/1.19.1/skills/better-interface/SKILL.md`.
- 값이 전부 CSS·Tailwind·Motion 기준이라 웹 화면 전용이다(데스크톱 Qt 앱엔 원칙만 참고).
- `design-bakeoff`와 겹친다. `variant`는 bakeoff의 Claude 시안 뽑기와, `better-interface`는 bakeoff 0-b(UX 원칙 점검)와 비슷하다.
- `afk`(몇 시간 혼자 고치고 커밋)는 전역 규칙 8과 충돌하니 쓰지 않는다.
- `~/.claude` 세션의 스킬 목록에는 `interfaces:*` 스킬이 안 보였다(설치 후 재시작 전이었을 수 있음 — 확인 필요).

## 할 일

1. 이 세션의 스킬 목록에 `interfaces:better-interface`가 있는지 먼저 본다. 없으면 사용자에게 `/reload-plugins`를 치라고 한다.
2. 범위는 **첫 화면(「내 칠판」 목록 + 빈 칠판이 열리는 진입 흐름)** 하나로 좁힌다. 칠판 전체는 너무 커서 스킬이 스스로 범위를 줄이게 되므로 처음부터 정한다.
3. `better-interface`를 실행한다. 고치지는 않는다(보고서만). 스킬이 렌더 확인을 원하면 `npm run dev`(포트 5190) 또는 `python web/server.py`(5191)로 띄워 직접 본다.
4. 보고서를 `~/.claude/design-system/ux-principles.md`·`preferences.md`·`projects/easy-cad.md`의 기존 판정과 비교한다. 사용자가 이미 정한 취향과 부딪히는 지적, 새로 건질 지적을 가른다.

## 끝의 기준

- 보고서 한 장이 실제로 나왔다.
- 「쓸 만한 지적 N개 / 이미 아는 것 N개 / 틀리거나 취향과 충돌 N개」로 정리해 사용자에게 보여 줬다.
- 유지·삭제(`claude plugin uninstall interfaces@interfaces`)·`design-bakeoff` 0-b와 연결 중 하나로 결론을 냈다. 결론이 `~/.claude` 쪽 변경(스킬·settings)이면 제안만 하고 `~/.claude` 세션에서 처리한다.
- 확인할 것: 평소 "이 화면 봐줘"라고 할 때 `design-bakeoff` 대신 `better-*` 스킬이 저절로 불리는 충돌이 있는지(이 세션의 스킬 목록 description끼리 비교 + 실제로 한 번 말해 보기).
