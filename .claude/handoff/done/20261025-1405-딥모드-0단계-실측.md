# 딥모드(§8 항목66) 0단계 실측 — 편집장 계획·재료 모으기의 시간·크레딧

생성: 2026-10-25 14:05

배경: 2026-10-25 세션에서 딥모드를 계획서 `docs/EasyCAD_계획.md` §8 항목66으로 적고 커밋함(`4031b1c`).
시안(사용자 판정 끝): https://claude.ai/artifact/5NrYb2RJ2yV56dbawvwSRo — ① 질문지 ② 지면 계획 ③ 완성 지면(어텐션 논문).
사용자 판정: 목표 = 「한 판에 보고 빠르게 이해」. 음성 해설·차례로 나타나기는 버림. 시안에서 겹친 곳은 줄 높이를 고정해서였음 → 실제는 앱이 꼭지 높이를 먼저 재고 놓기.
결과 모양 = 분량 보고 앱이(한 장 또는 프레임 여러 장). 그래프는 종류를 고르고 바꿀 수 있게(사용자 제안).

할 일(0단계): 구현 전에 실제 KAIROS로 재기만 한다(앱 코드는 안 고침, 실측 스크립트는 `tools/`에).
1. 주제 셋 — 논문(어텐션), 송신 장비(예: ATSC 3.0 송신기), 시사(웹 검색이 필요한 최근 주제).
2. 편집장 단계: 질문 + 질문지 답(시안 ①의 기본값) → 꼭지 5~9개 계획 JSON(꼭지마다 모양·재료 출처). 모델 후보: claude-opus-5-5(정리 문서와 같은), 비교로 하나 더.
3. 재료 단계: 계획의 꼭지마다 기존 길을 동시에 — 웹 검색 `easycad/ai/board_chat.py`(Exa), 공공 데이터 `kr_tools.py`, 그림은 견적만(`/estimate`, 실제 생성은 하지 않거나 1장만).
4. 잴 것: 단계별 시간·크레딧(응답 `billing`·`credits`), 계획 품질(꼭지가 주제에 맞나, 지어낸 숫자 있나 — 숫자마다 출처 있는지).
5. 결과를 `docs/history/2026-10.md` 끝과 계획서 항목66 「열린 질문」 자리에 적고, 1단계(그래프 물건) 착수 여부를 사용자에게 묻는다.

키: Easy CAD는 `easycad-gateway.key` 전용(memory `ai-gateway-key-location`). 끝의 기준: 주제 셋 모두 계획 JSON이 나오고, 단계별 시간·크레딧 표가 history에 있음.
