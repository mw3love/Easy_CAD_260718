# 화살표 속성 리뷰 — 남은 2건(S자 곡선 / 직각화살표 최소 스텁 길이)

생성: 2026-08-31 08:50

## 배경

사용자가 화살표 속성패널 관련 4가지를 "검토해봐"로 요청(스크린샷 3장 첨부). 코드로
원인을 확인한 뒤 4개 중 2개(채움 행 노출, 양방향 화살촉 드래그 미리보기)는 이미 이
세션에서 고쳐 커밋했다(`ca721f9`, `8b86050`, 전체 pytest 1090종 통과 + 실제 창
스크린샷 확인 완료). 남은 2개는 사용자가 "1번·4번은 다음에"로 미뤘다 — 구현이 아니라
**아직 방향 확정 전 리뷰만 끝난 상태**다.

## 남은 항목 1 — 곡선 화살표를 두 번 꺾이게(S자)

- **요청**: 화살표 속성 '종류' 드롭다운의 곡선 아이콘이 지금은 "한 번만 부푸는 활" 모양인데,
  두 번 꺾이는 S자로 바꿔달라는 취향 요청. 버그 아님 — 디자인 변경.
- **원인/구조**: `easycad/canvas/core_shapes.py:3721` `_ArrowItem.apply_curved()` — 양끝이
  도형에 안 붙은 자유 화살표는 제어점 2개(`_ctrl1`/`_ctrl2`)를 **같은 방향(nx,ny)·같은
  오프셋(off)**으로 대칭 배치해 단일 bulge를 만든다(3734~3739행). 드롭다운 아이콘
  (`core_constants.py:302` `_arrow_kind_icon`, `kind=="curved"` 분기)도 정확히 같은 단일
  quadTo bulge 로직이라 실제 결과와 일치한다.
- **바꿀 곳**: 저 두 지점(제어점 오프셋 공식 + 아이콘) 둘 다. 제어점을 서로 **반대 방향**으로
  오프셋하면 S자가 된다. 양끝이 도형에 붙은 경우(3740행 분기, 각 끝 법선을 따라가는 tangent
  기반)는 배치에 따라 이미 자연스러운 S자가 나올 수 있어 **그쪽은 안 건드려도 될 가능성이
  높다** — 착수 시 먼저 그 경로도 확인.
- **판단 기준**: "몇 번 꺾일지"는 오프셋 부호/크기 하나로 정해지는 단순 변경이라 별도
  deep-interview 없이 바로 구현 가능. 다만 아이콘도 같이 갱신해야 실제 결과와 일치한다는
  점을 놓치지 말 것(이번 세션에서 확인한 두 지점의 로직이 지금은 완전히 동일하다는 게 핵심
  근거였음).

## 남은 항목 2 — 직각화살표 머리쪽 선 길이가 짧아 "무너져" 보임

- **요청**: 스크린샷에서 직각 엘보 화살표가 도형에 진입하는 마지막 구간이 너무 짧아
  화살촉이 꺾이는 지점과 겹쳐 보임. 최소한 "텍스트+여백 정도"의 길이는 보장해달라는 요청.
- **원인(코드로 확인·재현 스크린샷까지 완료)**: `_route_ortho`(`core_shapes.py:8362`)가
  도형에 수직으로 붙는 진입/이탈 스텁 길이를 `clearance`(기본 12px) 또는 연결도형용
  `conn_clear = clearance * _CONN_CLEAR_MULT`(`_CONN_CLEAR_MULT=3.0`, 8286행 → 기본 36px)
  로 고정한다. 이건 순수 라우팅 여유값이고, 화살촉의 실제 렌더 크기
  (`_head_size() = max(width*3.2, 11.0) * head_scale`, `core_shapes.py:5224`/`4016`)와
  전혀 무관하게 정해진다. 펜을 굵게 하거나 속성패널 "머리크기" 배율을 올리면 화살촉이
  꺾이는 지점을 덮어버린다 — 재현: 스텁 20px·머리 11px(기본값)만으로도 이미 빠듯함을
  스크린샷으로 확인(스크립트: 이 세션의 scratchpad, 재현 필요하면 같은 방식으로 다시
  스크립트 작성).
- **바꿀 곳(제안, 미확정)**: 스텁 길이 계산에 `max(clearance, head_size * k)` 식 하한을
  추가 — 단 `_normal_stub`/`_route_ortho` 호출부가 여러 곳(qc-dot 생성·화살표 도구 그리기·
  reroute 등)이라 head_size를 그 시점까지 안 넘기는 경로가 있을 수 있음, 인자 전달 경로부터
  확인 필요.
- **왜 다음 세션으로 미뤘는지**: `_route_ortho`/A* 라우팅 코드는 이 프로젝트에서 **가장
  스턱루프가 잦았던 민감 영역**(768케이스 회귀 스윕 이력, `docs/pitfalls.md` "라우팅(A*/
  직교 엘보)" 참조)이라, 검토만 하고 바로 손대지 말고 별도 세션에서 deep-interview로
  범위(최소 스텁을 얼마로 잡을지, 기존 밀집 문서 성능/회귀 스윕에 영향 없는지, qc-dot
  드래그 중 라이브 미리보기(`set_ortho_preview`)에도 반영할지)부터 잡고 착수하는 게
  안전하다고 판단했다(사용자도 이 판단에 동의).
