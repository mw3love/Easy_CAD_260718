## 무엇을
웹 칠판 대화창에서 「송신소 계통도 그려 줘」·「점검 순서 흐름도 그려 줘」 → **고칠 수 있는 진짜 상자 + 상자에 붙은 화살표**가 칠판에 놓이게.
Magic Board 처음 약속 「말하면 그려지고, 그린 것은 끝까지 고칠 수 있다」의 웹 쪽 빈칸(CLAUDE.md `## 목표`).

## 왜 지금
- 2026-11-02~03 실검증(공개 칠판 「검증 본부」 `?board=gr58kfxs`)에서 「계통도 그려 줘」가 대화로 떨어져 SVG 코드 글이 나왔음(사용자: 일반 사용자는 당황).
- 11-03에 임시로 막음(커밋 `4e4e2c7`): 그림 느낌 말이면 그림, 아니면 되묻기 「✏️ 아이콘(SVG)으로 / 🎨 이미지로」, 답 속 SVG는 그림 칸으로.
  하지만 아이콘 길은 아이콘 하나용 — 화살표가 상자에 **붙지 않고** 그냥 선. 근본 해결이 이 기능.

## 재료(이미 있는 것)
- 데스크톱: `easycad/ai/text_to_flow.py`(AI는 「내용 설계서」 JSON만 — §8 항목52), `easycad/fileio/flow_spec.py`(배치 규칙: 담당 띠·칸·줄, Qt 비의존),
  그리기 `host_fileio._build_flowspec_items`(Qt). 웹 베끼기(`easycad/ai/board_trace.py`)가 「서버가 데스크톱 엔진을 부르고 .ecad 아이템을 돌려주면 칠판이 그림」 선례.
- 웹: 화살표 붙기 `web/src/next/connect.js`, 길 찾기 `route.js`(데스크톱 `_route_ortho`와 대조 시험), 되묻기 `route.decide`·`board_chat.maybe_diagram`(지금은 기본 icon).

## 먼저 할 일(계획 — 코드는 사용자 승인 뒤)
1. `text_to_flow`·`flow_spec`·`_build_flowspec_items`를 읽고, Qt 없이 .ecad 아이템(rect·symbol + 붙은 sarrow `bind1/bind2`)까지 만들 수 있는지 확인(사진→도면 `photo_ops.ops_to_sketch`처럼 Sketch로?).
2. 0단계 실측: 진짜 KAIROS로 3~4문장(계통도·순서도·조직도·마인드맵)의 시간·크레딧·품질(`tools/` probe 스크립트 관례).
3. 길: 새 kind `diagram` → 되묻기 기본을 icon → diagram으로, 대화창 「+」 도구 목록에 넣을지(사용자 「+」 = 이미지·아이콘·인터랙티브 HTML·Deep Mode).
4. 결과 막대·이어 고치기(「상자 하나 더」 등)는 데스크톱 §8 항목51~54 원칙(결과는 바로 넣고 아니면 Del, 배치·색은 앱이 정함) 참고.
5. 끝의 기준·시험(e2e 가짜 서버 + 진짜 KAIROS 실측) 정해서 사용자에게 계획 보여 주기.
