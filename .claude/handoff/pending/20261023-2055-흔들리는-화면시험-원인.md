## 할 일
1. 각 시험을 반복 실행해 실패율부터 잰다(예: `npx playwright test e2e/flow25-meeting-live.spec.js -g "연결 닫혀도" --repeat-each 10`).
2. flow25: 연결이 끊기는 순간과 「앞 연결 소리만큼 밀림」(`sent0`) 계산 사이에 소리 덩이가 하나 더 들어가는 타이밍 경쟁인지 — 시험의 기다림이 고정 시간인지, 앱(`web/src/next/mic.js`·회의 코드)의 밀림 계산이 덩이 경계에 민감한지 코드로 짚는다. 앱 버그면 앱을, 시험의 가짜 마이크 타이밍이면 시험을 고친다.
3. flow23: 전체 실행 때만 실패 → 앞 시험이 남긴 상태(같은 서버 `web/.e2e-data`, 칠판 이름, 서버 PDF 쪽 그림 만들기 속도) 의심. 실패 때 trace(`test-results/…/trace.zip`)로 어느 단계가 안 보였는지 먼저 본다.
4. 고친 뒤 각 시험 `--repeat-each 10` 전부 통과 + 전체 실행 2번 통과면 끝. `docs/pitfalls.md`의 두 흔들림 줄은 원인·해법으로 고쳐 쓴다.
