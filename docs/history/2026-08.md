**선택 미니패널을 속성 dock으로 통합 완료(2026-08-01, 커밋 `996eb5c`, 실조건검증 ✓)** —
사용자 피드백: 선택 위를 따라다니던 플로팅 컨텍스트 툴바(M3 #15)가 우측 속성 dock과
색·선스타일이 겹쳐 방해로 느껴짐. 색·선스타일 빠른버튼은 dock에 이미 동급이 있어 제거,
dock에 없던 4개(도형바꾸기·화살표종류·곡선반경·방향뒤집기)만 dock 폼 행으로 이관
(`QFormLayout.setRowVisible`로 선택 종류별 노출, 핸들러는 그대로 재사용). 부수 정리:
상단바 화살표 도구 클릭 시 뜨던 종류 선택 메뉴 폐지(클릭=항상 sticky 종류로 바로 무장,
종류 변경은 dock에서) · "다른 색…" 다이얼로그를 채움/선색 공통으로 통일(전엔 채움만
왼쪽 열 숨긴 비-네이티브, 선색은 OS 네이티브로 서로 달랐음). 스모크 328종.

⚠ **속성 dock 크기 미성장 버그 발견·수정(같은 커밋)** — 선택 종류가 바뀌어 노출 행 수가
달라져도(네모 7행→화살표 9행) `_refresh_properties()`는 행 노출만 토글하고 패널 위젯
자체를 그 크기에 맞게 키우지 않았다(`adjustSize()`는 창 리사이즈 코드에만 있었음). 그
결과 창을 한 번도 리사이즈 안 한 앱 기본 크기(1200×800)에서 화살표를 선택하면 스핀박스
(두께·폰트·반경)가 옛(더 좁은) 패널 크기에 짓눌려 13px까지 줄어 텍스트 디센더가 잘렸고,
창을 한 번이라도 리사이즈하면 그 코드가 우연히 실행돼 정상으로 보였다 — 사용자가 이
재현 패턴("작은 창=깨짐, 최대화 후 복원=계속 정상")을 직접 관찰해 제보. 진단 중 QSS
`font-weight`·`QStyleSheetStyle` 강제전환·DPI 재계산 신호 가설을 순서대로 시도했으나
전부 곁가지였음(스턱루프 규칙 11-b 발동, 실기기 반복 재현으로 최종 확정). `_refresh_
properties()`에 `activate()+adjustSize()+_reposition_panels()`를 추가해 선택이 바뀔
때마다 패널이 항상 현재 내용에 맞게 다시 커지도록 수정 — 실제 창(오프스크린 아님)에서
재현 스크립트로 수정 전후 패널 크기(170×270→170×334로 정상 성장)를 직접 실측 확인.
부수: 토스트 라벨 스타일시트 오타(중괄호 중복) 수정.

이 과정에서 **"실조건 검증은 사용자에게 요청" 관행 자체를 재검토**(사용자 지적: "니가
직접 프로그램을 키고 로그를 볼 수는 없냐") — 이 환경은 Bash가 사용자와 같은 대화형
데스크톱 세션이라 `QT_QPA_PLATFORM=offscreen`만 빼면 실제 창·콘솔 로그를 직접 확인할
수 있음을 확인, 전역 CLAUDE.md 규칙 11-d를 "시각 렌더"에서 "시각·실행 확인"으로 확장하고
아래 작업 규칙도 갱신(커밋 `d326752`).

**qc-dot/hover-port 통합 + 커넥터 UX 정밀화 완료(2026-08-01, 커밋 `e2aea6f`·`5101661`·
`b1a5cbb`, 실조건검증 ✓)** — 8포트 세션(2026-07-29) 이후 사용자가 Lucid와 대조하며 발견한
3건을 같은 세션에서 연쇄로 수정.
- **qc-dot 리사이즈 오판정 수정**(`e2aea6f`) — 2026-07-30에 변 리사이즈 핸들과 qc-dot을
  하나의 점으로 통합했을 때, 점 자체가 이미 그 축 방향으로 offset돼 있어 "바깥으로 당기기"가
  항상 리사이즈로 판정되던 버그(화살표가 안 생김) — 이 점에서 리사이즈 기능을 제거하고 화살표
  전용으로 되돌림(모서리 대각 핸들이 리사이즈 계속 담당). 이어서 Lucid 대조로 ⓐ qc-dot이
  연결되거나 드래그 중이면 4점 전부 테두리 위로 동시 수렴(일부만 다르면 "왜 이 점만" 혼란
  유발 — 4점 동시 전환) ⓑ 드래그 중엔 꼭짓점 리사이즈 사각·회전 점을 숨겨 변 점 4개만 노출.
  연결 판정(`_qc_has_connection`)은 `boundingRect()`가 자주 호출하는 경로라 itemChange의
  `ItemSelectedChange`에서 무효화하는 캐시 도입.
- **빈 캔버스 드롭 + 즉시생성 + 화살표 우선**(`5101661`) — ① qc-dot·hover-port 드래그가 스냅
  대상 없는 빈 캔버스에 떨어지면 바인딩 없는 화살표를 남기지 않고 원본과 같은 도형을 그
  자리에 만들어 함께 바인딩(`_qc_spawn_dup` 공유) ② hover-port 제자리 클릭은 종전엔 선택만
  되고 한 번 더 눌러야 도형이 생겼는데 qc-dot 클릭과 동일하게 즉시 도형+화살표 생성
  (`_side_from_normal`) ③ 사용자 재피드백으로 드래그 고스트에서 도형 박스를 빼고 화살표만
  남김(박스가 커서를 따라가면 "도형을 옮기는" 조작처럼 읽힘).
- **qc-dot/hover-port 시스템 통합**(`b1a5cbb`) — 사용자 관찰("qc-dot이 4분면 점과 다른
  차별점이 있나?") 확인 결과 기능은 이미 동일했고 남은 차이는 qc-dot이 미연결 시 테두리
  밖으로 뜨는 gap뿐(선택 순간 점 위치가 튀는 비일관성 유발) → `_qc_dot_rects()`가
  `_shape_ports()`를 그대로 사용(gap 로직·관련 캐시 전량 제거), 이원 상태필드(`_qc_*`)를
  `_hp_*` 하나로 병합, 중복 렌더 함수(`_qc_paint_ghost`·`_qc_target_rect`) 삭제. 의도적으로
  유지한 비대칭: 선택된 도형의 접속점은 어느 도구에서든 잡히고, 미선택 도형은 select
  도구에서만(그리기 방해 방지) — "무엇을 잡느냐"가 아니라 "어느 도구에서 잡히느냐"라 사용자가
  지적한 비일관성과 무관. ⚠ 통합 중 발견: `boundingRect()`가 회전 핸들(좌상단에만 존재)과
  접속점을 union할 때, 종전엔 미연결 qc-dot의 큰 gap이 좌상단 쏠림을 우연히 상쇄했는데
  접속점이 항상 테두리에 붙는 지금은 그 상쇄가 사라져 중심이 8px씩 어긋남(이미지 삽입
  중심좌표 테스트로 발견) → 회전 핸들이 튀어나온 만큼 네 변에 동일 선패딩해 대칭 복원.

Rejected: 렌더링(지속 접속점 표시)까지 뷰 레벨로 완전 통합 | 소유권 분리는 문제가 아니었고
(비일관성은 위치·동작이지 렌더 소유권이 아님) 블라스트 반경만 커짐. 스모크 330→331종.
Not-tested: 실제 마우스 드래그 손맛(합성 이벤트로 대체) · 회전/스케일된 박스에서 boundingRect
대칭 패딩의 여유가 정확히 맞는지(수치 계산만 검증).

**화살표 boundingRect/_content_rect 체인 최적화 완료(2026-08-01, 커밋 `9e218e9`, 프록시+실조건
확인)** — 계획서 §8 "다음 순서" 9번. 2026-07-30 다중선택 드래그 성능 수정 세션에서 화살표
200개 시나리오를 프로파일링하다 발견하고 원인만 특정해둔 채 미뤄뒀던 항목. cProfile 재실측
(합성 화살표 200개, 20개 다중선택 30프레임 드래그)으로 확정: `_PolyArrowItem`/`_ArrowItem`의
`boundingRect()`가 정점(끝점)마다 `_endpoint_rect`·`_inflate_to_hit`·`_handle_px`를 거쳐
각각 별도로 `_scale_or_1()`(=`_view_zoom_factor()`, 뷰 `transform().m11()` 조회)을 호출해
boundingRect 한 번에 5~6회씩 재조회하고 있었다(값은 호출 중 안 바뀌므로 순수 낭비). 추가로
`_hit_pad_local`/`_view_scale_or_1`이 2026-07-29에 도입된 `_view_zoom_factor` 캐시를 거치지
않고 `sc.views()[0]._view_scale()`을 매번 새로 호출하는 별도의 미캐시 경로로 남아 있었다
(당시 마이그레이션 누락 — 값은 동일: 메인 인터랙티브 뷰가 항상 `sc.views()[0]`이라 확인).

해법: `_scale_or_1`/`_hit_pad_local`/`_inflate_to_hit`/`_handle_px`/`_endpoint_rect`에 선택적
`scale`·`view_zoom` 파라미터 추가(기본값 None=기존 동작 그대로) — 두 `boundingRect()`가 뷰줌
값을 한 번만 읽어 아래로 넘기고, `_hit_pad_local`/`_view_scale_or_1`도 캐시를 재사용하도록
통일. `paint`·hover·mousePress 등 다른 호출부는 파라미터 생략 시 완전히 동일하게 동작해 무변경.
`_content_rect()`/`_head_points()`의 삼각함수 비용(`_pts` 의존 실기하 계산)은 손대지 않음 —
캐시하려면 모든 geometry 변경 지점에 무효화 훅이 필요해 이 CAD 앱(정확성이 성능보다 중요)에서
위험 대비 이득이 낮다고 판단.

실측(같은 합성 시나리오): `_view_zoom_factor` 호출 175,710→56,310회(-68%), boundingRect()
누적시간 2.718s→1.884s(-31%), 전체 시나리오 3.620s→2.960s(-18%). offscreen 스모크 331종
전원 통과 + 실제 창(오프스크린 아님)에서 도형 이동→화살표 추종을 스크린샷으로 재확인(첫 시도는
바인딩 로컬점 좌표계를 잘못 잡은 테스트 하네스 버그로 화살표가 원점 근처로 붕괴돼 보였음 —
`_RectItem`은 rect를 절대좌표로 갖고 pos()는 0,0이라 바인딩 로컬점도 절대좌표여야 했는데
"박스 크기 내 상대좌표"로 잘못 넣었던 것, 실제 코드가 아니라 검증 스크립트의 오류였음).
Rejected: `_view_zoom_factor`가 캐시하는 뷰 객체뿐 아니라 조회한 float 값 자체를 씬에 캐시(호출
수를 1회 미만으로) | 값 캐시는 줌이 실제로 바뀌는 정확한 시점마다 무효화해야 해 앱 전역
히트테스트·핸들 크기가 걸린 상태라 잘못 무효화하면 블라스트 반경이 큼 — 이번엔 "호출 내 재조회
제거"(무효화 불필요, 항상 정확)로 범위를 좁힘. Not-tested: 실제 무거운 도면에서 `python run.py`
체감(합성 시나리오 프로파일링만).

**선택 강조·미니맵/속성패널 UX 폴리싱 완료(2026-08-01, 커밋 `4644590`~`8d5a983`, 부분
실조건검증 — 스모크 333종)** — 사용자가 Lucid 스크린샷과 실사용 중 지적한 것을 같은 날
연쇄로 처리한 세션. 문서 동기화 전 미푸시 상태로 10개 커밋이 쌓여 있었음.
  - **선택 강조 표시 근본 리팩터**(`4644590`·`cb4ed14`, **실조건검증 ✓** — 사용자가
    `python run.py`로 확인, "훌륭함") — 드래그선택(crossing) 미리보기가 축정렬
    `_content_rect` 박스를 그려 회전 도형이 어긋난 사각형으로 보이던 것을, crossing 판정이
    이미 쓰는 `_base_shape()`(회전·곡선 반영 실제 외곽선)로 교체. 이어서 개별 아이템 선택
    표시와 드래그 미리보기가 서로 다른 메커니즘으로 겹쳐 그려지며 생긴 문제(강조선이 중심선과
    안티에일리어싱이 섞여 옅어짐·cosmetic 펜이 줌 200%+서 사라짐·화살표 강조가 유독 두꺼움·
    타입별 표시가 다중선택 바운딩박스와 스타일 충돌)를 `_item_center_path`(패딩 없는 원본
    기하)·`_highlight_band`(두께 비례 폭 스트로크 후 `subtracted()`로 안쪽 절반 제거, Lucid식
    바깥쪽만)·`_paint_selection_highlight`로 통일해 근본 해결(`_HandleResizeMixin` 기본
    구현 + 8개 클래스의 개별 override 제거). Rejected: 강조선 폭만 줄이기 | 근본원인이 위치
    (중심 겹침)였지 폭이 아니었음.
  - **포트 예고점 억제 + 화살표 선택강조 캐싱**(`4ea581f`) — ⓐ `_draw_port_dots`가 도형
    이동·변형·러버밴드 드래그 등 진행 중에도 커서 위치만 보고 근처 도형에 포트 점을 계속
    그려 방해되던 것을, 7가지 드래그 상태 플래그 중 하나라도 켜져 있으면 조기 반환하도록
    수정. ⓑ 위 선택강조 리팩터가 `_PathItem`엔 캐시를 남겼지만 화살표 두 클래스엔 안 붙어
    포트 호버로 인한 잦은 리페인트와 겹쳐 "쓸수없는" 수준으로 느려졌던 것을 동일 캐시 패턴
    (`prepareGeometryChange()`에서만 무효화)으로 해결. 실측 27.1ms/call→0.127ms/call.
  - **상단바 그룹 구분 + 전체맞춤 미니맵 이관 + 반복클릭 버그**(`73b0b93`) — 상단바를
    파일/도구/편집·보기 3그룹으로 구분선 강조, 100%·전체맞춤 버튼 제거(휠줌·미니맵으로

  - **ⓐ 과발화(1차 보고)** — 축당 후보가 9개(좌/중심/우 × 좌/중심/우 전조합)라 「좌-중심」·
    「중심-우」처럼 기하적으로 의미 없는 교차 조합까지 매칭됐다. 같은 역할 3개 + 마주보는 변
    2개 = **축당 5개**로 정리(의미 없는 4개만 배제). 여기에 **전역 tie-break 도용 버그**도 발견·
    수정 — 무관한 위치의 다른 도형 중심이 우연히 근접 동률 범위에 걸리면 진짜 변 정렬을
    가로챘다(같은 상대 도형 내에서만 tie-break 적용하도록 스코프 축소).

    항상 정확히 일치한다(`center = left + width/2`가 양쪽에서 같은 오프셋). 그래서 "동률이면
    중심 우선"이라는 안정화 규칙이 **드물게 발동하는 미세조정이 아니라 상시 발동하는 규칙**

**실사용 버그 2건 + checked 상태 재조정(2026-08-02, 같은 날 3차 — 사용자가 실행 중 캡처로 재현
보고)**

1. **라이트 모드에서 패널·버튼·텍스트가 거의 안 보임** — 원인: `_apply_theme(dark=False)`가
   `app.style().standardPalette()`(Fusion "표준" 팔레트)를 그대로 썼는데, 이 PyQt6(6.10.2)/
   Windows 조합은 `styleHints().colorScheme()`가 OS 다크모드를 따라가 그 "표준" 팔레트 자체가
   다크(`Window #323232`)로 나온다 — 캔버스 배경만 명시적으로 흰색이라 밝아지고 패널 본문·
   버튼·제목/토스트 텍스트는 다크 색 그대로 남아 안 보였다. `_dark_palette()`처럼 고정 색
   `_light_palette()`(`host_widgets.py`)를 새로 만들어 OS 설정과 무관하게 해결 — 접근색도
   이 기회에 다크/라이트 공통 코랄로 통일(예전엔 라이트만 블루 `#1f7ae0`로 스코프 밖 취급했던
   결정 폐기).
2. **토스트 메시지(다크/라이트 전환·핀 토글 등) 위치가 처음엔 좌상단, 몇 번 쓰면 하단중앙** —
   원인: `_ToastLabel.showMessage()`가 `_reposition_toast()`를 `.show()` **전**에 호출하는데,
   `_reposition_toast()`는 `toast.isVisible()`이 참일 때만 동작했다. 첫 표시 시점엔 아직
   `hide()` 상태라 재배치를 건너뛰고 생성 시 기본 위치(좌상단)에 남았고, 이후 창 리사이즈로
   `_reposition_toast()`가 다시 불릴 때(그땐 이미 보이는 상태)만 하단중앙으로 옮겨갔다 —
   순서 의존 버그. `_reposition_toast()`에서 `isVisible()` 가드를 제거해 호출 순서와 무관하게
   항상 재배치하도록 고쳤다(숨긴 토스트를 옮겨도 부작용 없음, 더 견고).
3. **checked 버튼 테두리가 상시 소란스러움** — 1차(같은 날 버튼 accent 커밋)는 hover/checked/
   pressed 전부 배경 틴트, 2차(이번 세션 초반)는 "블록처럼 보인다"는 지적으로 checked를
   테두리만으로 바꿨는데, 스냅·격자(기본 ON)·좌측 「도형」 탭(상시 하나 선택)처럼 **평소에도
   계속 켜져 있는 토글**에 테두리 박스가 늘 떠 있어 "항상 튀어 보인다"는 재지적. 사용자에게
   3가지 대안(배경 틴트로 복귀/테두리 유지+채도만 낮춤/상시·일시 구분 처리)을 제시해 "옅은
   배경 틴트로 전환"(alpha 35, hover의 40보다도 낮음)으로 확정 — hover/pressed는 순간
   피드백이라 그대로 진하게 유지. 교훈: **상시 지속 가능한 상태(checked)와 순간적 상태
   (hover/pressed)는 같은 강도로 강조하면 안 된다** — 상세: `~/.claude/design-system/
   projects/easy-cad.md`.

톤)에 머물러 있었다 — 실측으로 확인. getter/setter 도입으로 두 모듈 다 항상 최신값을 읽게
통일해 해결.
