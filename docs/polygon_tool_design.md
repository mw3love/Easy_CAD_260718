# 다각형/폴리라인 도구 — 설계 확정 (2026-08-18, 구현 대기)

deep-interview로 확정한 설계. **아직 코드 구현 전** — 이 문서 + `docs/EasyCAD_계획.md` §8의
포인터만 보고 다른 PC에서 바로 이어서 구현하면 된다.

## 배경

사용자 요청: "선 도구는 한 번만 하는게 아니라 클릭-클릭으로 꺾이는 포인트 만들어서 계속
그릴 수 있게(예: 삼각형, 오각형 등등) 하는 건 어떤지?" — 지금 "선(line)" 도구는 rect/ellipse와
같은 단순 드래그 생성(press-drag-release = 선분 1개, `core_view.py`)뿐이라 여러 점을 찍어
다각형을 만드는 길이 없다.

## 확정 결정

1. **별도 "다각형" 도구 신설.** 기존 "선(line)" 도구(드래그=직선 1개)는 완전 무변경 —
   같은 도구 안에서 클릭 수로 분기하는 안은 "이 클릭이 서로 다른 두 동작을 불러온다"는
   암묵적 규칙이 생겨 기각. 새 도구는 새 단축키 하나를 받는다(현재 1~9 중 비어있는 키
   확인 필요 — `core_view.py:83` 부근 `Qt.Key.Key_*` 매핑 참조. 1~8은 이미 선택/사각형/
   화살표/텍스트/원/선/펜/번호가 차지, 9는 화살표 종류 전환용으로 이미 씀).

2. **종료 방식 — 닫기·열린종료 둘 다 지원.**
   - 시작점 재클릭 → 닫아서 **다각형 완성**(새 닫힌 도형 클래스).
   - 더블클릭 또는 Enter → 그 자리에서 **열린 폴리라인**으로 종료(닫힌 도형 아님).
   - Esc → 그리던 것 취소(기존 `_on_escape` 관례 재사용).

3. **데이터모델 — 진짜 새 도형 클래스(추천안 채택).**
   `_LineItem` 여러 개를 체인으로 잇는 안은 기각(변마다 따로 선택·이동되어 "하나의 도형"으로
   다룰 수 없음 — 삼각형 예시에 안 맞음). `_RectItem`/`_EllipseItem`급의 새 클래스가 점 목록을
   가진다:
   - **닫힌 다각형**: 채움색·통짜 이동·리사이즈 지원. 구조상 나중에 TRIM/EXTEND(§8 항목17과
     같은 지문)를 붙일 수 있게 설계(당장 구현은 안 함, 아래 "제외 범위" 참조).
   - **열린 폴리라인**: 여러 변을 가진 열린 선. 채움 없음.
   - **구현 시 판단 필요(사용자 확인 없이 코드로 결정)**: 닫힌/열린을 완전히 다른 클래스
     둘로 만들지, 하나의 클래스에 `closed: bool` 플래그로 통합할지는 실제 착수 시
     `_PolyArrowItem`(`core_shapes.py:3760`, 이미 다중 점 목록을 들고 있는 기존 클래스)의
     내부 점 저장 구조를 먼저 확인해 재사용 가능성부터 검토(전역 CLAUDE.md 규칙 2 "손안의
     카드" 정신 — 새 클래스 두 개보다 기존 구조 재사용이 가능하면 그쪽이 더 단순).

## 1차(v1) 구현 범위

**포함**:
- 새 "다각형" 도구(그리기 상호작용 전체 — 점 추가, 미리보기 선, 닫기/열린종료/취소).
- 닫힌 다각형: 채움색, 통짜 이동, 리사이즈(균일 스케일 — 기존 도형과 같은 `_HandleResizeMixin`
  경로).
- 열린 폴리라인: 이동(통짜), 리사이즈.
- undo/redo(기존 `capture_state`/`capture_geom` + `push_undo_*` 패턴 재사용 — 새 서브타입
  전용 undo 로직을 새로 만들 필요는 없을 가능성이 높음, 착수 시 확인).
- **`.ecad` 저장/불러오기**(`item_to_dict`/`dict_to_item`) — 이건 "후속으로 미뤄도 되는지"를
  사용자에게 재확인했고, **v1에 포함하기로 확정**. 이유: 저장이 안 되면 다각형을 그려도 파일을
  닫고 다시 열면 사라져 실사용이 불가능하다(단순 프로토타입 검증용이 아니라 실제로 쓸 기능).

**제외(후속 라운드로 미룸)**:
- DXF 내보내기(`dxf_export.py` 확장).
- TRIM/EXTEND 연동(§8 항목17과 동급 지원). 기존 도형이 이 지원을 갖추는 데만 7단계가
  걸렸던 전례(§8 항목17, `docs/route_review_2026-08.md` 계열) — 새 도형 클래스에 한 번에
  다 지우려 하면 리스크가 크다. 데이터모델은 나중에 TRIM을 붙일 수 있게는 설계해 두되,
  실제 자르기 로직은 이번 라운드 스코프 밖.
