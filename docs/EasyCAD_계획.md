## 3. 아키텍처 핵심 결정

**A. 좌표계 / 단위**
CAD 왕복과 A-size 인쇄를 위해 **mm 단위 월드좌표**를 채택(화면 픽셀과 분리). 무한 캔버스는 월드좌표 위에서 팬/줌. Y축 방향(CAD는 Y-up, 화면은 Y-down)은 DXF 입출력 시 변환.

**B. 문서 모델 (가장 중요한 리팩터 지점)**
pasteflow 편집기는 QGraphics 아이템을 사실상 모델로 쓰는 구조로 보임(`확인 필요` — grep만 했고 완독 안 함). Easy CAD는 결국 **모델↔뷰 분리**가 필요하다:
- 이유: DXF 매핑 · Undo/Redo · 저장/열기 · "객체 개별 인식" 전부 깨끗한 엔티티 모델을 전제로 함.
- 방침: v1은 속도를 위해 기존 아이템 구조를 최대한 재사용하되, **각 아이템이 직렬화 가능한 의미정보(타입·기하 파라미터)를 반드시 지니게** 설계한다. 정식 문서모델은 Phase 3(DXF 직전)에 도입 — 그때 리팩터 규모는 pasteflow 코어 완독 후 확정.

**C. Undo/Redo**
`QUndoStack` 기반 커맨드 패턴으로 Phase 1부터 도입(뒤에 붙이면 고통). 모든 편집을 커맨드로.

      싸게 먹힘, 심볼 개수 증가에 가장 직접적으로 대응.
    - **리스트뷰 토글**(아이콘 그리드 ↔ 이름 전체가 보이는 목록) — 아이콘을 아무리 키워도
      팔레트 버튼 라벨이 6자로 잘리는(`entry["name"][:6]`) 근본 제약이 남아 있어, 이름을
      끝까지 보려면 그리드 자체를 대체하는 리스트 레이아웃이 필요 — 검색창보다 큰 개편.
    - **최근 사용/자주 쓰는 심볼 상단 고정** — 폴더가 많아질수록 유용하나 "사용 빈도" 추적
      이라는 새 영속 상태(symbol_library.json 스키마 확장)가 필요해 셋 중 스코프가 가장 큼.
    - **[4번째 후보] 즐겨찾기(사용자 수동 지정) — 완료(2026-08-20)** — '내 심볼' 좌측
      패널 접기 재개편(CLAUDE.md "현재 상태" 참조) 작업 중 사용자가 "미분류가 애매해졌다,
      즐겨찾기로 바꾸면 어떤지" 제안한 것을 deep-interview로 스코프 확정 후 구현: `folder`와
      같은 패턴의 `"favorite": true/false` 필드, '내 심볼' 최상단(미분류 위) 이중표시
      섹션(구글드라이브 관례 — 원본 폴더+즐겨찾기 둘 다 노출), 우클릭 토글 1개, 드롭 대상
      아님(우클릭 전용), 폴더 완전삭제 시 별도 코드 없이 자동 정리. 상세:
      `docs/history/2026-08.md` "'내 심볼' 즐겨찾기 기능 구현 완료" 참조. 검색창·리스트뷰·
      최근사용 3개는 여전히 착수 보류(아래 판단 기준 유지) — 착수 시 이 3개는 서로 겹치는
      목적(둘 다 "자주 쓰는 걸 상단에")이라 함께 deep-interview로 재확인할 것.

23. **Mermaid·SVG AI 다이얼로그 재정리** — **Stage 1~6 전부 완료(2026-08-19)** + 2026-08-20 후속
    라운드(UX 개선 다수). 원문 판단: 실사용 피드백이 이어져 계속 열려 있는 상태로 취급.
    상세: `docs/EasyCAD_계획_완료기록.md` 「§8 항목23」.

24. **'내 심볼' SVG 파일 내보내기/공유 — 착수 보류(2026-08-20 제안)** — 즐겨찾기 기능
    (항목22 4번째 후보) deep-interview 도중 사용자가 "도형 우클릭 → 파일 위치 열기 →
    사용자끼리 SVG로 공유"를 제안했으나, 지금 구조는 심볼 하나하나가 독립 SVG 파일이
    아니라 `symbol_library.json` 하나에 도형정보+썸네일로 저장돼(SVG로 가져온 심볼도
    가져오는 순간 앱 내부 도형 데이터로 변환되고 원본 파일 경로는 안 남음) "이 심볼의
    원본 파일"이 존재하지 않는다 — 즉 이 요청은 "파일 위치 열기"가 아니라 **심볼→SVG
    직렬화(내보내기) 로직을 새로 만드는 일**이라 즐겨찾기와는 별개 스코프로 판단해
    보류(사용자 확인). 착수 시 deep-interview로 범위(단일/다중 내보내기, 저장 위치,
    가져오기 쪽 왕복 보장 여부 등) 정리 필요.

25. **'내 심볼' 개별 썸네일 색상 대비 — 착수 보류(2026-08-26, 최종 검수 Phase 6에서
    원인 규명)** — `_render_symbol_thumbnail`이 등록된 도형의 실제 잉크색을 그대로
    쓰는데(예: 다크 캔버스에서 검정 펜으로 그린 심볼은 어두운 색 그대로 박힘) 기본
    팔레트 아이콘(`_shape_icon`)은 테마 적응 흰색이라 대비가 갈려 옅게/안 보이게
    느껴진다 — 렌더링 결함이 아니라 색상 대비 문제로 확정. 자동 색보정("항상 밝게
    보정")은 실제 캔버스에 배치했을 때의 진짜 색과 미리보기가 달라지는 WYSIWYG
    트레이드오프가 있어 디자인 판단 필요, 착수 시 deep-interview로 보정 방식(배경만
    대비 확보/항상 흰 배경 강제/사용자 선택) 정리. 상세: `docs/history/2026-08.md`
    "최종 검수 Phase 6".
26. **마인드맵 빈 노드 취소 시 남는 고아 화살표 — 착수 보류(2026-08-26, 최종 검수
    Phase 6에서 재확인)** — Tab/Enter로 만든 자식/형제 노드는 `mm_create_child`/
    `mm_create_sibling`/`mm_create_in_direction`이 새 노드+화살표를 **즉시 커밋**
    (`push_undo_add_many`)한 뒤 편집모드로 들어가, 빈 텍스트인 채로 편집을 취소해도
    되돌리는 코드가 없다 — 2026-08-24 도입 당시 "의도적 최소범위"로 남겨둔 결정
    그대로 아직 미해결. 고치려면 "이 편집 세션이 방금 생성한 빈 노드의 첫 편집인지"를

## 9. 검증 철학

각 Phase는 "작동"이 아니라 **검증 가능한 목표**로 닫는다. 특히 Phase 3(DXF)·Phase 1(PDF)은 실제 AutoCAD/인쇄물로 확인하는 **실조건검증**이 완료 기준 — 헤드리스·합성지표로 "됐다" 하지 않는다.
