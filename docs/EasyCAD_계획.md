## 3. 아키텍처 핵심 결정

**A. 좌표계 / 단위**
CAD 왕복과 A-size 인쇄를 위해 **mm 단위 월드좌표**를 채택(화면 픽셀과 분리). 무한 캔버스는 월드좌표 위에서 팬/줌. Y축 방향(CAD는 Y-up, 화면은 Y-down)은 DXF 입출력 시 변환.

**B. 문서 모델 (가장 중요한 리팩터 지점)**
pasteflow 편집기는 QGraphics 아이템을 사실상 모델로 쓰는 구조로 보임(`확인 필요` — grep만 했고 완독 안 함). Easy CAD는 결국 **모델↔뷰 분리**가 필요하다:
- 이유: DXF 매핑 · Undo/Redo · 저장/열기 · "객체 개별 인식" 전부 깨끗한 엔티티 모델을 전제로 함.
- 방침: v1은 속도를 위해 기존 아이템 구조를 최대한 재사용하되, **각 아이템이 직렬화 가능한 의미정보(타입·기하 파라미터)를 반드시 지니게** 설계한다. 정식 문서모델은 Phase 3(DXF 직전)에 도입 — 그때 리팩터 규모는 pasteflow 코어 완독 후 확정.

**C. Undo/Redo**
`QUndoStack` 기반 커맨드 패턴으로 Phase 1부터 도입(뒤에 붙이면 고통). 모든 편집을 커맨드로.

    39.9초·44.5크레딧(gemini-3.6-flash 때 약 25초·24크레딧), 선택 고치기 33초·30크레딧에 고른 칸만 바뀜(나머지 11칸 그대로).

    할 일 표·일정·예산 숫자·인용(21초·13크레딧, 1장), 「그림을 가운데로 크게」 → 그림 혼자 10칸·big(25초). 「도면 검사」 0개.
58. **보드 디자인 개편(A 디자인 언어 + B 한 장 채우기)** — **승인**(2026-10-17). 계기: 같은 논문(1706.03762)을 세 모델로 만든 보드가
    "잘 만든 PPT·인포그래픽"보다 못하고 모델 차이가 안 보인다(사용자). 같은 GPT 설계서 블록 8개를 아티팩트로 디자인한 시안
    (https://claude.ai/artifact/XhRKRh4BUjVb8hXstQb6Cw)은 한 장에 들어가고 인포그래픽처럼 보임 → 한계는 모델이 아니라 앱의 그리기(모든 블록 같은
    회색 상자·얇은 글씨·줄 높이 맞춤 빈칸·2장 넘김). 원칙(AI는 내용, 앱은 모양)은 그대로. 순서·단계마다 커밋:
    ① 글자 힘 — 글 상자 굵게(.ecad·내보내기 유지) + 글자 크기 단계 하나(큰 제목·헤드라인·블록 제목 굵게·본문·작은 글씨).
    ② 블록 역할별 모양 — 주인공 블록 하나는 진한 면(검은 보드에선 밝은 면), 숫자는 윗선 타일, 카드는 왼쪽 색 띠, 목록·의의는 위 가는 선, 흐름도는
    옅은 강조 면 위 가로 흐름, 상자 안 상자 금지, 강조색 코랄 + 보조 파랑. AI는 `hero`(주인공 블록)·`headline`(짧은 한 줄)만 더 낸다.
    ③ 한 장 채우기 — 줄 높이 맞춤 대신 열 쌓기, 남는 높이는 그림·흐름도가, 넘치면 간격 → 본문 한 단계(바닥값까지) → 그다음에만 2장.
    ④ 넘침 정리 — 숫자는 줄바꿈 대신 축소, 쪽 번호 자리를 제목 폭에서 빼기, 칸 밖 글은 「도면 검사」가.
    끝의 기준: 같은 논문 세 모델 모두 1장, 카드마다 내용이 높이의 3/4 이상, 넘침·겹침 0, 검은 보드·흰 종이 출력 읽힘, 회의록도 안 깨짐, 기존 테스트
    통과, 시안과 나란히 캡처해 사용자 판정. 하지 않음: AI가 좌표·HTML(편집 불가·겹침), 문서마다 색 뽑기(②가 자리 잡은 뒤 따로), 이미 만든 보드 바꾸기.
    **진행**(2026-10-17): ①~④ + 격자 맞춤·채우기 완료 — 실제 KAIROS 세 모델 모두 1장(전후 https://claude.ai/artifact/GNttktnDi8RtewZJdJ8Z3M). 이어서 59.

    펼쳐져 사람이 골라 다시 정리할 수 있다(두 층 원칙 — 처음 쓰는 사람은 한 장을 바로, 숙련자는 조각으로). 보드 틀(16:9)은 유지(한 장 분량을
    눈으로 보여 주고 색·내보내기·끌어다 놓기의 과녁), 처음에 「한 장/펼쳐서」 고르는 메뉴는 없음. 순서:
    ① 디자인 구분 — 사용자 지적: 시안은 같은 무리끼리 색을 나눔(숫자 BLEU 주황·학습 시간 파랑, 열쇠 카드도 둘씩), 숫자는 테두리 있는 타일,
    핵심 원리 블록(어텐션 단계 + 수식)이 있음. → AI가 항목마다 무리(`groups`)를 달고 앱이 무리마다 색, 숫자 타일 테두리·단위 작게, 지시문에
    "핵심 원리는 단계 + 기호", 머리 구분선·저자 정보 오른쪽.
    ② 조각 펼치기 + 「보드로 정리」 — 조각 = 블록 후보 10~20개 + 원문 조각(그림·표·숫자·인용). 고른 것으로 오른쪽에 새 보드.
    ③ 끌어다 놓기 — 조각을 보드 위에 놓으면 보드가 자리를 내주며 다시 배치, 밖으로 빼면 조각으로. ④ 손 배치 → 출력 때 페이지로 나눔(틀 없이).
    완료 기준: 같은 논문으로 PDF → 한 장 보드 + 옆 조각 → 조각 하나 끌어다 넣기 → 여러 개 골라 「보드로 정리」 → PDF 출력이 실제 창에서
    끊김 없이, 디자인은 시안과 나란히 놓고 사용자가 합격. 제외: 처음 고르는 메뉴, 틀 없애기, AI가 좌표·HTML. 열린 질문: 경진대회 마감일,
    조각 수가 몇 개면 복잡해지나(②에서 실측), 원문 조각을 앱이 뽑나 AI가 고르나, ④의 페이지 나누기 방식, 조각 때문에 늘어나는 시간·크레딧.
