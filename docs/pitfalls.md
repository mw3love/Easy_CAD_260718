## Qt 시그널·이벤트 발화 조건
- `itemChange(ItemPositionChange)`는 `ItemSendsGeometryChanges` 플래그 없으면 아예 발화하지
  않는다 — `_ConnectorLabel` 자유이동 구현 중 발견. (`2026-07.md` FigJam 라벨 갭)
- `scene.changed`는 콘텐츠 변경에만 뜬다 — 휠줌·팬 같은 순수 뷰 트랜스폼은 안 탄다. 미니맵·
  화살표 reroute를 이 시그널에만 걸면 줌/팬 후 갱신이 안 됨. (`2026-07.md` 미니맵,
  `2026-08.md` boundingRect 최적화)
- 합성 `QMouseEvent`(press+move)는 이 앱 창에서 씬(`mouseGrabberItem`)에 델타로 반영되지
  않는다 — 오프스크린/자동화로 드래그를 재현할 수 없다는 뜻. 결과 상태가 필요하면 API 호출로
  대체(예: `setPos`/`apply_*` 직접 호출). pyautogui 같은 OS 레벨 자동화도 이 창에서는 클릭·선택
  자체가 안 먹힘(원인 미확정). (`2026-07.md` M4-4, `2026-08.md` 스마트 정렬 가이드)
- `QTabWidget`은 탭 전환과 무관하게 내부 `QStackedLayout.sizeHint()`가 **가장 큰 탭 크기로
  고정**된다 — 콘텐츠 크기로 패널이 줄어들게 하려면 탭 대신 `setVisible()` 토글. 숨김→재표시
  직후 `adjustSize()`는 레이아웃 무효화가 아직 반영 전이라 stale — `layout().activate()`를 먼저.
  (`2026-07.md` 캔버스-퍼스트 레이아웃)
- Qt 레이아웃은 부모 체인을 따라 **지연 전파**된다 — 자식 하나만 `activate()+adjustSize()` 해도
  조상(중첩 3단 이상)의 캐시된 sizeHint가 그 시그널 핸들러 안에서 즉시 안 바뀔 수 있다. 조상까지
  전부 activate 후 adjustSize. (`2026-08.md` 속성 dock 크기 버그 2건)
- `QToolButton` 등에 `.setStyleSheet(...)`를 조상 위젯(메인윈도우·패널 body)에 걸면, 그 스타일
  규칙이 특정 위젯을 안 가리켜도 **하위 위젯 전부**(형제로 있는 `QAbstractSpinBox` 포함)가
  `QStyleSheetStyle` 렌더 경로로 강제 전환돼 스핀박스 `sizeHint`가 짧아지고 폼 행이 겹친다 —
  2026-07-31 사고와 같은 메커니즘이지만 이번엔 최상위(`self`)에 걸어 재발했다. 스핀박스가 없는
  컨테이너(툴바 등)는 컨테이너 단위로 걸어도 되지만, 스핀박스와 형제인 버튼은 **위젯 각각에
  개별로** 걸어야 한다. (`2026-08.md` 버튼 코랄 accent 회귀)
- `QMessageBox`(또는 임의 모달)를 모킹 없이 테스트에서 직접 호출하면 헤드리스 환경엔 누를
  사용자가 없어 `.exec()`가 영원히 블로킹 — 스위트 전체가 "멈춘 게 아니라 조용히 도는" 상태로
  보인다. 모든 모달 경로는 테스트에서 모킹 필수. (`2026-07.md` DXF/.ecad 통합)
- `QGraphicsItem`에 Qt 자식(`setParentItem`)이 하나라도 있으면, `paint()`에서 분절된
  `QPainterPath`(moveTo/lineTo로 gap 있는)를 그려도 `QGraphicsScene.render()`/
  `QGraphicsView.grab()` 경로에서는 그 gap이 사라지고 닫힌 도형으로 보인다 — `item.paint()`를
  직접 호출하면 정상 렌더되므로 데이터·분기 자체는 문제 없음. 자식이 없는 말단 아이템 쪽에서
  같은 시각효과를 내는 식으로 우회. (`2026-08.md` 포트-테두리 trim, 위키
  `easycad-qgraphicsitem-자식있는아이템-paint-gap-무시.md`)

## 좌표계·변환
- `drawForeground`의 painter는 Qt가 이미 **씬 좌표계**로 매핑해 넘긴다 — 여기에 다시
  `mapFromScene()`을 적용하면 이중 변환이 되어 원점 근처에서만 우연히 맞아 보인다. 미니맵
  인디케이터가 이 버그로 실사용에서만(데모 좌표는 우연히 통과) 어긋났다. 같은 증상이 재발하면
  트리거보다 **핵심 계산 자체**부터 재검증. (`2026-07.md` 미니맵)
- `fitInView(KeepAspectRatio)`는 뷰포트 종횡비가 극단(가로로 김)이면 레터박스가 커져 안의
  인디케이터가 실제보다 작아 보인다 — 미니맵류 패널은 좁고 세로로 긴 비율로 설계. 두 번
  반복된 함정(2026-07-28 dock, 2026-07-29 플로팅 패널). (`2026-07.md` 미니맵·캔버스-퍼스트 레이아웃)
- `_HandleResizeMixin.boundingRect()`가 회전 핸들(좌상단에만 존재)과 접속점을 union할 때, 한쪽만
  비대칭으로 튀어나오면 도형 중심이 실제 콘텐츠 중심에서 어긋난다 — 대칭 패딩으로 상쇄해야 함.
  (`2026-08.md` qc-dot/hover-port 통합)
- 아이템의 rect가 절대(씬) 좌표를 그대로 품고 `pos()`는 (0,0)에 남는 패턴(마우스로 그린 도형)이
  흔하다 — 정렬·스냅 기준점은 `pos()`나 로컬 원점이 아니라 `_content_rect()` 좌상단의
  `mapToScene()` 값을 써야 한다. (`2026-07.md` 그리드/스냅투그리드)
- `_scale_or_1`류 헬퍼가 아이템 자체 `.scale()`만 보고 뷰의 줌 배율을 무시하면, 확대할수록
  선택 테두리·핸들이 도형과 함께 커진다 — 뷰의 `isInteractive()`인 메인 캔버스 줌을 별도로 곱해야
  화면 픽셀 크기가 고정된다(Figma/AutoCAD 관례). (`2026-07.md` 실사용자 DXF 검증)
- 위 헬퍼가 이미 뷰 줌을 곱해서 반환한다는 걸 잊고 새 핸들 코드에서 뷰 줌을 **한 번 더** 곱하면
  반대 방향 버그가 난다(줌에 비례해 커지는 게 아니라 반비례해 작아짐) — 세그먼트(직교 커넥터
  중간점) 핸들만 다른 핸들과 다르게 줌마다 크기가 달라 보였던 원인. 같은 이유로 "안티에일리어싱
  여유분" 같은 사소한 상수도 씬 단위로 남겨두면 확대할수록 화면에서 그대로 커진다(포트-테두리
  커버 마스크의 `+1.0`) — 화면에서 항상 같은 크기여야 하는 값은 전부 `_scale_or_1()`로 나눠야
  한다는 원칙을 새 코드를 추가할 때마다 다시 확인할 것. (`2026-08.md` 후속 2 — 줌 이중스케일)

## 히트테스트·법선(포트/스냅)
- 도형 꼭짓점(마름모 E/W, 사각형 대각)은 두 변이 만나는 자리라 "최근접 변 하나"로 법선을 구하면
  변 선택이 임의가 되어 좌우 포트가 위아래로 드나든다 — 마름모는 의도된 축(N/S=수직·E/W=수평)
  강제, 사각형은 가까운 변 기준으로 강제. 보정은 **공유되는 저수준 함수**(`_nearest_border`)
  자체에 둬야 한다 — 상위 호출부 중 하나(포트 목록)에만 넣으면 다른 호출부(자동 라우팅)는
  여전히 옛 버그를 갖는다. (`2026-08.md` 8포트 확장)
- 재부착(끝점) 드래그 중 화살표가 **자기 자신의 다른 구간**에 스냅될 수 있다 — 스냅 함수에
  `exclude=self`를 반드시 넘겨야, 시각적으론 붙어 보여도 바인딩이 None으로 남는 사고를 막는다.
  (`2026-07.md` M4-4 최종 잔여)
- `QGraphicsItem.contains()`/`shape()`는 "클릭하기 쉬운 히트 밴드"이지 실제 기하 경계가 아니다
  — 속 빈(NoBrush) 도형은 `_base_shape()`가 `_EDGE_HIT_MIN`만큼 부풀린 스트로크를 반환해,
  테두리 2px 바깥도 `contains()`가 `True`를 준다. "테두리 두께 중심 안쪽/바깥쪽" 같은 기하
  판정엔 `contains()`를 쓰지 말고 도형별 실제 경로(사각형 `rect()`, 원 `addEllipse`, 심볼
  `_sym_path()`, PathItem `path()`)로 직접 확인해야 한다. (`2026-08.md` 미선택 도형 테두리
  연속 호버)

## 상호작용 설계(특례 vs 규칙)
- "이 아이템 종류만 다르게 반응해야 한다"는 요구가 나오면, 그 종류를 판별하는 `if` 를 관련
  상호작용 함수마다 심는 방향(특례 산개)으로 먼저 가지 말 것 — 이 앱은 호버·큐닷·드래그가
  이미 병렬 시스템 여러 개(코스 매칭용/이산 매칭용/선택 전용/렌더 전용)로 나뉘어 있어서,
  특례를 하나씩 넣을 때마다 다른 병렬 시스템에 같은 구멍이 남는다 — 3라운드 동안 매번 다른
  함수에서 같은 증상이 재발했다. 먼저 "이 요구를 특수 케이스가 아니라 **전체에 적용할 보편
  규칙 변경**으로 풀 수 있는가"를 검토한다(예: "포트는 화살표만" → "드래그는 항상 화살표만,
  전 도형 공통"). 되면 특례 코드가 아예 필요 없어지고, 병렬 시스템 개수와 무관하게 한 번에
  막힌다. (`2026-08.md` 포트 상호작용 재설계 — 4라운드, 사용자가 직접 패턴을 지적하며 전환)

## 라우팅(A*/직교 엘보)
- A* 격자(Hanan grid)에 화살표 자신의 좌표를 노드로 넣으면, 다른 화살표와의 교차점에 노드가
  얹혀 회피 벌점이 "눈멀게" 된다 — 회피 레인은 도형 팽창 모서리만으로 충분. (`2026-07.md`
  화살표-화살표 교차 회피)
- "부재"(증상: 안 나온다·안 걸린다)를 조사할 땐 **발생한 사례가 아니라 차단된 지점**을 찾아야
  한다. 게이트 플래그를 로그에 심어도, 발화한 줄만 grep하면 차단당해 안 찍힌 줄을 놓친다 —
  스턱루프 3라운드의 근본원인. (`2026-08.md` 스마트 정렬 가이드, 전역 규칙 11-b 「부재 확인」)
- 매 프레임(드래그 중) 국소 재정렬로 경로를 patch하는 접근은, 서로 다른 프레임의 판단이 서로의
  결과를 덮어쓰는 구조라 다중 프레임 드래그에서 표류한다 — "새로 그리기와 동일하게 전체
  재계산"으로 메커니즘 자체를 바꿔야 안정된다(3차 시도 끝에 확정). (`2026-08.md` 8포트 확장)
- 드래그 재설계로 점 개수가 매 프레임 바뀔 수 있게 되면, press 시점에 캡처한 "몇 번째 점"
  인덱스가 다음 프레임엔 범위 밖(IndexError)이 될 수 있다 — 인덱스는 매 프레임 유효 범위로
  재계산. (`2026-08.md` 8포트 확장, 끝점 드래그 크래시)
- "승자 하나 고르기" 안정화 규칙은, 두 후보의 거리가 **수학적으로 항상 일치**하는 경우(같은
  크기 도형의 좌/중심/우)엔 미세조정이 아니라 상시 발동하는 규칙이 되어 특정 정렬(변 정렬)이
  원리적으로 표시 불가능해진다 — 동률이면 하나만 고르지 말고 역할 전부를 동시 표시.
  (`2026-08.md` 스마트 정렬 가이드)
- 인접(마주보는 변) 후보에만 "교차축 범위가 겹쳐야 후보 인정" 게이트를 걸면, 두 도형이 정확히
  일치해도 게이트가 안 열려 후보에 못 오른다 — 같은 역할 매칭엔 이 게이트가 없는데 인접에만
  건 비대칭이 원인. 게이트 완화(+여유)가 아니라 **제거**가 정답이었다. (`2026-08.md` 스마트
  정렬 가이드)
- 그리드 A*에서 실좌표 시작/끝점(포트 등)을 `Math.round(x/cellSize)`로 그리드 셀에 스냅할 때,
  두 축을 독립적으로 반올림하면 원래 축 정렬(수평/수직)이었던 진입 방향이 반올림 오차로 대각선이
  될 수 있다 — 진입 방향과 무관한 축까지 통째로 반올림하는 게 원인. 첫/끝 구간에 직각 코너를
  강제 삽입(`fixOrthogonal`)해야 항상 축정렬이 보장된다. Python/Qt A*가 아니라 JS 프로토타입
  (`web_prototype/astar.js`)에서 발견 — 좌표 반올림이 있는 격자 라우팅이면 언어 불문 재발
  가능. (`2026-08.md` 웹 전환 실험)
- A* 탐색이 아예 실패하는 경우(예: start/end가 `bounds` 밖)의 폴백 경로는 위 `fixOrthogonal`을
  거치지 않고 원시 좌표를 그대로 반환하면 대각선 한 방으로 장애물을 관통한다 — "찾은 경로"와
  "폴백 경로"를 별도 반환문으로 나눌 땐 축정렬 정규화를 둘 다에 적용해야 한다. 대규모(도형
  17개·화살표 22개) 자동 스트레스 테스트 중 발견. (`2026-08.md` 웹 전환 실험 — 인터랙션
  스트레스테스트)
- **[Python/Qt 본체, 2026-08-07 재현·해결] `_on_scene_changed`(host_canvas.py)의 "region이
  화살표 bbox와 겹치면 reroute" 필터는 순수 선택(클릭, 이동 없음)의 선택강조 리페인트 region도
  "겹침"으로 잡는다** — 실제 도형이 안 움직여도 트리거된다. 화살표가 캔버스 폭넓게 뻗은
  밀집 도면(장애물 18개짜리 KBS 실도면 변환본)에서는 이 리페인트 region이 거의 모든 화살표
  bbox와 겹쳐, 클릭 5회 → `reroute()` 39회 → `_astar_ortho` 174회 → 총 56.7초(cProfile 실측,
  `docs/history/2026-08.md` "§8 항목15 실사용 피드백" 참조)로 이어졌다. 바로 아래 웹
  프로토타입 항목과 같은 계열의 함정(관련 없는 리페인트/이동이 전체 재계산을 유발)이 Python
  본체에서도 재현된 것 — "선택했을 뿐인데 재계산이 도는가"는 두 스택 모두에서 재발 가능한
  패턴으로 간주. **해법**: `boundingRect()`는 선택되면 핸들 여백만큼 커져(`_HandleResizeMixin`
  공통 동작) `sceneBoundingRect()`로 "실제 변경 여부"를 판정하면 선택 자체가 이미 오탐이 된다
  — 핸들 여백이 빠진 `_content_rect()`(도형별 override, 타이트 경계)를 씬좌표로 매핑해 매
  `_on_scene_changed` 호출마다 이전 스냅샷과 비교하고, 실제로 달라진 아이템의 rect 합집합만
  화살표 bbox 겹침 판정에 쓰도록 교체(`host_canvas.py` `_sync_geom_snapshot`). region=None(
  테스트 강제호출)은 기존처럼 무조건 전체 재검토 유지. 결과: 같은 재현 스크립트로 5클릭
  0.59초(120배)·`reroute()` 0회, 스모크 387종 전원 통과. 검증 중 발견: `load_document` 직후
  바인딩 정규화 reroute의 지연 `scene.changed` 신호가 **두 번째** `processEvents()` 틱에야
  전달된다 — 실사용은 마우스 클릭이 도착하기 전에 이미 소진되는 1회성 정착 비용이라 무해하지만,
  벤치마크 스크립트가 이 정착을 클릭 1회차 비용으로 오산할 수 있어 `tools/profile_reroute.py`도
  로드 후 `processEvents()` 1회를 추가해 정착시킨 뒤 측정하도록 함께 수정.
- 매 pointermove마다 전체 화살표를 재계산하는 방식(무관한 도형 이동도 장애물이 될 수 있어
  도입)은 도형 17개·화살표 22개 규모에서 이미 프레임당 평균 21.8ms(60fps 예산 16.7ms 초과)까지
  올라간다 — "드래그 중엔 연결된 화살표 + 이동한 도형과 bbox가 근접한 화살표만 재계산하고,
  드롭 순간에만 전체 재계산 1회로 정확성 보장"으로 바꿔 20개/31개 규모에서 프레임당 평균
  2.15ms(10배 개선)로 해결. 다만 이 근접(bbox margin) 판정은 휴리스틱이라, 아주 먼 거리를 빙
  돌아가는 화살표 경로 위로 무관한 도형이 옮겨지는 극단적 케이스는 드래그 도중엔 놓칠 수
  있음(드롭 시점엔 항상 correct) — 실사용에서 체감되면 재검토. (`2026-08.md` 웹 전환 실험 —
  인터랙션 스트레스테스트)

## 렌더링(QPainter/QIcon/오프스크린)
- 오프스크린 플랫폼 플러그인(`QT_QPA_PLATFORM=offscreen`)에서 `QPainter`의
  `CompositionMode_SourceIn`/`DestinationIn`으로 SVG 아이콘을 런타임 재칠하면, 짧은 시간에
  CanvasWindow를 수십 개 생성하는 스모크 테스트에서 재현 가능한 네이티브 세그폴트가 났다 —
  QPixmap↔QImage 전환·premultiplied 포맷 전환 등 4가지 변형을 다 시도해도 재현됐고, 캐싱으로
  호출 빈도를 줄여도 재현됨(호출 "횟수"가 원인이 아니었음). 해법: 합성모드를 아예 안 쓰고
  `QImage.setPixelColor()` 픽셀 루프로 RGB만 교체 — 상세와 시도한 변형 전부는 wiki
  `easycad-svg아이콘재칠-QPainter합성모드-세그폴트.md` 참조. (`2026-08.md` 아이콘 색 중립화)
- `QPen`의 **기본 joinStyle은 `BevelJoin`**이다 — 명시하지 않고 예각 폴리곤을 `drawPolygon`
  하면 꼭짓점이 모따기된다. 화살촉 삼각형(30° 어깨)에서 실제로 어깨가 45°로 잘렸고,
  `_ArrowItem`은 처음부터 `RoundJoin`을 명시해 둬 멀쩡했기에 "직각 화살표만 깎인다"로 보였다.
  펜을 만들 땐 capStyle·joinStyle을 항상 명시할 것. wiki
  `easycad-qpen-기본joinstyle-예각폴리곤-모따기.md` 참조. (`2026-08.md` Lucid 대조 UX 시리즈)

## 검증 방법론
- 오프스크린(headless) 통과는 "해결"이 아니다 — 지속연결 초안이 offscreen은 통과했지만 실제
  GUI에서 버그가 났다(플로팅→고정 부착점으로 재설계). 전역 규칙 11-c "정직한 상태표기" 참조.
- 헤드리스는 한글 폰트가 없어 tofu(□)로 렌더된다 — 텍스트 정렬·크기 확인은 반드시 비-헤드리스
  `QGraphicsView.grab()` 또는 `python run.py` 실화면으로. (`2026-07.md` Mermaid import)
- `python run.py`를 사용자에게 대신 실행해 달라고 요청하기 전에, 이 환경은 Bash가 사용자와
  같은 대화형 데스크톱 세션이므로 `QT_QPA_PLATFORM=offscreen`만 빼고 직접 실행하면 실제 창·
  콘솔 로그를 스스로 확인할 수 있다(전역 규칙 11-d, 2026-07-31 확립). 정말 대리 불가능한 것
  (마우스 드래그 손맛·실기기)만 사용자에게 남긴다.
- 같은 증상이 두 번째로 재발하면(스턱루프 트립와이어) 트리거만 좁혀가지 말고 **핵심 계산 자체**
  부터 재검증한다 — 트리거를 의심하는 건 계산이 이미 맞다는 전제가 깔린 것인데, 그 전제가
  틀렸을 때는 헛수고다(미니맵 이중변환 사례).
- **시각 버그를 "재현 안 됨"으로 닫기 전에 사용자와 같은 「줌 배율」인지 확인한다.** 크기가 펜
  폭·화면 px에 고정된 결함(예: joinStyle 모따기 ~0.5 씬단위)은 저배율에서 안티에일리어싱에
  원리적으로 묻힌다 — 화살촉 어깨 모따기를 3라운드 동안 재현 못 한 유일한 이유가 이것이었고,
  사용자 스크린샷의 미니맵 배율 표시(2863%)를 읽고 같은 배율로 렌더하자 즉시 재현됐다.
  (`2026-08.md` Lucid 대조 UX 시리즈)
- **"A만 이상하고 B는 멀쩡"할 땐 두 경로의 같은 부분을 나란히 diff한다** — 직각 화살표만
  머리가 깎였는데 곡선·직선은 멀쩡했다면, 두 클래스의 *화살촉 그리는 코드 두 줄*을 대조하는
  게 가장 빠른 진단이다(실제로 그렇게 원인이 즉시 나왔는데 3라운드 뒤에야 했다).
- **시각 결함의 회귀 테스트는 렌더 픽셀로 못 박는다** — 로직 어서션으로 못 잡는 종류이므로
  `QGraphicsScene.render()`로 QImage에 그린 뒤 특정 좌표의 채움 여부를 검사한다. 판정 지점은
  추정하지 말고 **정상/버그 두 버전을 각각 렌더해 실측**으로 고르고, 테스트를 넣은 뒤 반드시
  **수정을 일시 되돌려 실제로 실패하는지** 확인한다(통과하는 테스트가 그 버그를 잡는다는 보장은
  없다). (`2026-08.md` `test_arrowhead_shoulders_not_beveled`)
- **`QDialog`를 `.show()`/`.exec()` 없이 만들어 자식 위젯의 `setVisible()` 결과를 테스트할 땐
  `isVisible()`이 아니라 `isHidden()`을 본다** — `isVisible()`은 최상위 창이 실제로 화면에
  떠야 True가 나오므로, 다이얼로그를 생성만 하고 안 띄운 헤드리스 단위테스트에선 `setVisible
  (True)`를 호출해도 항상 False다. `isHidden()`은 명시적 hide 여부만 반영해 최상위 표시상태와
  무관하게 정확하다. (`2026-08.md` PDF 내보내기 메뉴 통합 §8 항목14, `_PdfExportDialog` 테스트)

- `.ecad`에 필드를 추가할 때는 항상 "키 없으면 안전한 기본값"으로 로드하게 만든다(예: 옛
  `routing:"ortho"`는 반경 0으로, `col_widths` 개수 불일치는 균등폭으로). 새 기본값이 옛 파일의

- 반환 계약이 이미 25곳 이상에서 소비되는 함수(`load_document`의 `int` 반환)는 타입을 바꾸지
  말고 별도 함수(`load_document_layers()`)로 분리 — 회귀 폭 최소화. (`2026-07.md` 레이어 패널)

## 파일 분할(리팩터링)
- 거대 파일을 쪼갤 때 공유 상수만 따로 뽑아 `_constants.py` 같은 별도 파일을 만들면, 그 상수를
  실제로 쓰는 다른 leaf 모듈(위젯·다이얼로그 등)과 원본 파일 양쪽에서 서로 참조하다 순환
  임포트가 되기 쉽다 — 상수는 그걸 실제로 쓰는 다른 콘텐츠와 **같은 leaf 파일**에 두는 편이
  안전하다. (`2026-08.md` 프로젝트 구조 정리, `host_constants.py` 폐기 → `host_widgets.py`로 재배치)
- 한 클래스(믹스인)의 메서드들이 다른 클래스(아이템)의 함수를 부르고, 그 아이템 클래스가 다시
  그 믹스인을 상속하는 식으로 **진짜 순환 의존**인 부분은 억지로 여러 파일로 쪼개지 말 것 —
  함수-지역 임포트를 여러 곳에 흩뿌려야 해서, 이미 버그가 잦았던 영역일수록 위험만 커진다.
  하나의 파일로 유지하는 쪽이 더 안전한 경우가 있다(크기만으로 분할 여부를 정하지 않는다).
  (`2026-08.md` — `annotator_core.py`를 16개 대신 `core_shapes.py` 하나로 유지)

## AI 이미지 생성(에셋 디자인)

  수정해서 다시 그려줘"식 프롬프트는 이전에 확정된 디테일(예: 십자선)이 조용히 빠질 수 있고,
