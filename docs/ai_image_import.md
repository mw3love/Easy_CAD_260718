# AI 이미지→도면 (앱 내장) — 설계

**목표:** 앱 안 입력창에 도면 이미지(+보충설명 텍스트)를 넣으면, 원본과 최대한 비슷하되
**도면으로서 역할에 충실한** 편집가능 도형을 캔버스에 생성한다.

기존 `docs/image_to_ecad.md`(2026-07-21)와의 관계: 그 문서는 **Claude Code 세션 안에서**
사람이 돌리는 워크플로다. 이 문서는 같은 목적을 **앱 런타임**으로 옮긴 것이고, 뒷단
(`fileio/sketch_build.py` 빌더)은 그대로 재사용한다. 앞단(이미지 이해)만 세션 vision에서
게이트웨이 호출로 바뀐다.

## 확정 결정 (deep-interview 2026-08-11)

- **실행 위치: 앱 내장.** 게이트웨이(Mindlogic/factchat)를 앱이 직접 호출. 사용자가 앱만
  켜고 쓸 수 있어야 진짜 기능이다.
- **중간 표현: 좁은 JSON**(아래 스키마). Mermaid 배제 — 좌표가 없어 원본 배치를 버린다
  (`docs/EasyCAD_계획.md` §6·`image_to_ecad.md` 「스코프 밖」에서 이미 같은 이유로 결론).
  `.ecad` JSON 직접 생성도 배제 — 바인딩 인덱스·`#AARRGGBB`·`auto_route` 함정을
  `sketch_build.Sketch`가 이미 감춘다.
- **좌표 전략: 하이브리드.** 배치는 원본 픽셀을 따라가되, 축 정렬·직교 라우팅·라벨은 앱
  관례로 정리한다. "사진 같은 그림"이 아니라 "그 도면을 다시 그린 도면"이 목표.
- **사용자 조작은 1단계.** 입력창 하나(이미지 + 보충설명). 아래 파이프라인의 다단계는
  전부 내부 구현이지 사용자 워크플로가 아니다.

## 실측 (2026-08-11, 실제 키로 게이트웨이 왕복)

`docs/reference/image (1).png`(1920×1080, KBS 송신소 계통도 — 밀집 실도면)로 측정:

| 조건 | 결과 |
|---|---|
| `GET /models/` | 79종. `gemini-3.6-flash`·`gpt-5.6-*`·`claude-*-5` 등 |
| `json_schema` strict | 통함 (구조화 출력 사용 가능) |
| `gemini-3.6-flash` 전체 1패스 | 44초, shapes 39·edges 29·unknown 8 |
| `claude-sonnet-5` 전체 1패스 | **504 Gateway Timeout** (절반 축소해도 동일) |
| `claude-sonnet-5` 구획 크롭 3× | 35초, shapes 13·edges 10 — 라벨 한글까지 정확 |
| `gemini-3.6-flash` 같은 크롭 3× | 17초, shapes 9 — 작은 `M`/`S`를 부모 박스에 병합 |

**세 결론:**

1. **레이아웃 패스 기본 모델은 gemini 계열.** Claude 계열은 이 게이트웨이에서 밀집 도면
   전체 이미지에 대해 타임아웃한다(모델 능력이 아니라 게이트웨이 시간 제한).
2. **크롭 = 줌인이 실제로 인식률을 올린다.** 전체 패스는 `Eurotek Link 1` 옆의 작은
   `M`/`S` 서브박스를 통째로 누락했고, 같은 구획을 3배 확대해 넣으니 전부 잡혔다.
   작은 요소는 모델 성능 문제가 아니라 **입력 픽셀에 정보가 없는 것**이다.
3. **패스별로 모델을 다르게 쓴다.** 같은 크롭에서 `claude-sonnet-5`는 13개(작은 `M`/`S`를
   개별 박스로 분리), `gemini-3.6-flash`는 9개(부모 박스에 병합)로 읽었다 — 후자가 2배
   빠르지만 세부를 뭉갠다. → **P1 개괄은 gemini(전체를 처리할 수 있는 유일한 쪽),
   P2 타일은 claude(크롭이라 타임아웃 안 나고 세부가 살아난다)**가 합리적 분담이다.
   B단계에서 실제 도면으로 재확인할 것.

## 파이프라인 (내부 4패스, 사용자에겐 버튼 하나)

```
이미지 + 보충설명
      │
      ├─ P1 개괄 패스   전체 이미지 1회 → 구획(그룹 박스) 경계 + 대략 블록
      │                 산출: 타일 목록. 밀집도가 낮으면 여기서 끝낼 수도 있음.
      │
      ├─ P2 타일 패스   구획별 크롭 ×N (병렬) → 정밀 shapes/edges/unknown
      │                 좌표는 크롭 오프셋을 되더해 전체 좌표계로 복원.
      │
      ├─ P3 병합·정규화 타일 경계를 넘는 연결 잇기, 중복 제거,
      │                 축 스냅(하이브리드 전략), 라벨 정리
      │
      └─ P4 에셋 패스   unknown 항목만 크롭 재전송 → SVG 생성
                        → svg_import.py → 네이티브 벡터 + 「내 심볼」 등록
                        실패하면 통짜 상자로 남기고 목록에 표시(전체는 이미 완성돼 있음)
```

**P4가 실패해도 P3까지의 도면은 쓸 수 있다** — 이게 단계를 나눈 실질적 이득이다.

## 중간 JSON 스키마

`sketch_build.Sketch` 호출 인자를 그대로 미러링한다. 필드를 늘리기 전에 빌더가 그걸
지원하는지 먼저 확인할 것.

```json
{"shapes": [{"id":"s1","kind":"box","x":120,"y":80,"w":200,"h":90,"label":"1TV 송신기"}],
 "edges":  [{"from":"s1","to":"s2","label":"","head":true}],
 "unknown":[{"id":"u1","x":400,"y":300,"w":60,"h":60,"desc":"원형 스위치"}]}
```

- `kind`는 빌더 어휘로 제한(`box`·`ellipse`·`decision`·`terminal` 등 `_SYMBOL_KINDS`).
- `unknown`은 "사각형·타원으로 표현 못 하는 것"만 — P4의 작업 큐다.
- 프롬프트에 ⚠ **"실제로 그려진 연결선만"**을 반드시 넣는다(`image_to_ecad.md`의
  2026-07-21 실조건 함정 — 논리적으로 있어야 할 것 같은 선을 모델이 만들어낸다).
- 점선 그룹 테두리(구획 박스)는 shapes에서 제외하도록 명시(안 하면 전부 상자로 들어온다).

## 단계 계획 (각 단계 검증 기준)

**A. 게이트웨이 클라이언트** — `easycad/ai/gateway.py` 신설. **완료(2026-08-11)**.
`Paste_flow/pasteflow/ocr_engine.py` 패턴 이식(base_url 정규화·모델 폴백·크레딧 조회·
오류 분류). 키는 QSettings + 환경변수 폴백. 폴백 트리거는 원본(`model_not_found`)에
`timeout`을 추가 — 이 게이트웨이의 실패 모드가 모델 부재가 아니라 밀집 도면 504이므로.
→ 검증(실호출, 2026-08-11): 모델 목록 79종 조회·크레딧 잔액(4085.66/5000.0)·이미지
왕복("42" 정확히 읽음) 전부 정상.

**B. 헤드리스 파이프라인** — `tools/ai_sketch.py`. P1~P3 + `Sketch` 변환. **완료(2026-08-11)**.
→ 검증: pytest 21종(mock, 좌표복원·타일격자·중복제거·축스냅 등 순수로직)
+ `docs/reference/image (1).png`(KBS 1TV 실도면) 실행 — P1 gemini 36.5초
shapes=29·edges=21·unknown=8(임계 초과로 타일링 6개), P3 최종 shapes=128·edges=131·
unknown=22. 위 baseline(전체 39 vs 크롭 13)의 "타일링하면 뚜렷이 많아져야 성공" 기준을
3배 이상으로 충족. `tools/screenshot.py --doc` 렌더 육안 확인 — 다중 TX 체인 토폴로지·
"모악산 On-Air Receiver"·"STL 주 (1701.750MHz, 5W)" 등 실제 도메인 라벨 정확 추출 확인.
⚠ 자동 타일링(`compute_tiles`)이 만든 타일이 이 실측(360×160 수동 크롭)보다 커서 claude가
6개 중 4개는 여전히 타임아웃 — 폴백은 정상 동작했으나 claude 세부 이득이 줄어듦(다음 튜닝
지점, `docs/pitfalls.md` "AI 게이트웨이 호출" 참조). 상세 경위: `docs/history/2026-08.md`
"§8 항목18 AI 이미지→도면 — A+B단계".

**C. 앱 통합** — 입력창(이미지 + 텍스트), 백그라운드 스레드, 진행 표시,
결과 삽입은 undo 1스텝. **핵심(입력창+스레드+삽입+undo) 완료(2026-08-11)** — 사용자가
"빠른 테스트"를 목적으로 요청, 취소 버튼과 **원본 반투명 언더레이 대조**는 스코프 축소로
이번 라운드 제외(나중에 추가 가능, 핵심 로직과 독립).
→ 검증(완료): pytest 8종(mock) + 실제 창(오프스크린 아님) + 실제 게이트웨이 호출로 종단
확인 — shapes 13·edges 10, 기존 도형 보존한 채 삽입, undo 1회로 정상 복원, 화살표
재라우팅·상태바 메시지까지 스크린샷 육안 확인. 상세: `docs/history/2026-08.md`
"§8 항목18 C단계".

**D. 에셋 패스(P4)** — unknown → SVG → `svg_import` → 상자 교체 + 라이브러리 등록.
→ 검증: 실도면의 안테나 픽토그램 1건 왕복.

## ⚠ 함정 (실측으로 확인된 것)

- **`urllib`로 이 게이트웨이를 호출하면 SSL 인증서 검증에 실패한다**(self-signed in chain).
  `openai` SDK / `httpx`(certifi 번들)는 정상. → 표준 라이브러리로 직접 치지 말 것.
- **`claude-*` 계열은 밀집 도면 전체 이미지에서 504.** 모델 선택을 사용자에게 열어두되
  기본값은 gemini 계열로. 폴백 체인 필수(`ocr_engine._call_with_fallback` 패턴).
- **좌표는 크롭 좌표계로 나온다.** 3배 확대해 보냈으면 `/3` 후 크롭 오프셋을 더해야
  전체 좌표계가 된다. P2→P3 병합에서 가장 틀리기 쉬운 지점.
- 비전 모델은 절대 픽셀 좌표를 완벽히 짚지 못한다. 언더레이 대조(C단계)가 사용자에게
  주는 보정 수단이고, 정밀도가 계속 문제면 OpenCV 기하 검출 하이브리드가 다음 카드다
  (지금은 입력이 폰 사진이라 이득이 적어 보류).
